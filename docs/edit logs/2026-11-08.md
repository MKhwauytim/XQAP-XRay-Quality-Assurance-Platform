## v160.0 — 2026-11-08 — Add (reports): port report tool, one HTML page that turns the raw workbook into the port report

**Why:** The owner wanted one HTML file they open, drop the raw Excel workbook into, and get the port report in the required formats (HTML, PDF, PowerPoint, Excel), without running scripts. Until now the Jeddah report came only from `scripts/export-port-report-static.mjs` in a developer shell.

**What changed:**
- **Shared steps, one copy.** Everything the script did after reading the sheets moved into `src/data/reporting/portReport/portReportBuild.ts`: port-name canonicalisation, the year and last-month filters, the workload tiers, the model, the slides, the observations and the data-workbook sheets plus their bytes. The population-sheet column rules moved from `scripts/lib/workloadSheets.mjs` into `workloadAggregate.ts`. The script and the tool both call these, so they cannot drift.
- **The tool.** `port-report-tool.html` is built by `npm run build:port-tool` into one self-contained file, `dist-tool/port-report-tool.html`. `dist/` is untouched, and `dist-tool/` is git-ignored.
  - A worker reads the dropped .xlsx with JSZip and streams each needed sheet's XML row by row (`readWorkbook.ts`), so a 318 MB workbook doesn't sit in memory as parsed sheets.
  - The page lists the ports, the years (checkboxes, for with or without 2024) and the last month, and fills in the cover period.
  - It downloads HTML, Excel, PowerPoint (`deckHtmlToPptx`, the in-app converter, now also returning the file for the zip), or all three in a zip.
  - PDF opens the report with the print dialog («حفظ كملف PDF»), so the PDF carries the embedded Somar font.
- The data workbook's cell font is now «Somar Sans», the installed family name; it was «Somar», which matched no installed font.

**Migration/rollback:** none. No workspace or file format changes. Rollback is reverting the commit; the script's command line and output are unchanged.
