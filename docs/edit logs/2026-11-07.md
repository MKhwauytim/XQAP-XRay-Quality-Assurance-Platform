## v159.16 — 2026-11-07 — Fix (months): pre-merge review of split and bulk move (re-projection, replicas, lost store, empty list)

**Why:** The parent session's pre-merge review of PR #231 found four data-integrity defects in the split and bulk-move write paths, plus several smaller gaps.

**What changed (reds, each with a test):**
- **Moved-back rows reappeared in the exceptional store.** `ensureAdhocSampleMaster` and `assignAdhocPlan` (through `replicaIndicesByRow`) re-project every VALID record row, `excludedByAdmin` included. A row moved back to the index is now marked `validation: { valid: false, reason: MOVED_TO_INDEX_REASON }` (the row is kept, never projected and never assigned). `restorePlan` and `alreadyMovedIds` skip invalid rows.
- **The record was written last.** `moveExceptionalCasesToIndex` now writes the record change first. If a later step fails, nothing re-projects the rows, and a re-run moves them again.
- **Fan-out replicas collapsed.** Only replica 0 moves; copies with `adhocReplicaIndex > 0` are skipped and counted. The month holds one row per image, so a second reviewer's assignment is no longer silently lost.
- **A split whose store write failed lost cases.** `alreadyMovedIds` re-projects each split record (`ensureAdhocSampleMaster`). It counts an id as moved only when the namespaced row is really in the store. Every `executeSplitMonth` run, restore-only included, does this first, so step 3 never removes a row that exists nowhere else.

**What changed (yellows):**
- Assign events only for ids that `appendSampleRows` actually appended, so a live month case keeps its owner, and only for employees that `findAssignableEmployee` accepts.
- An `"absent"` population is an error.
- `withLiveTotals` recomputes `totalActual` and the CertScan split from the live rows for both rewrites. Port and stage allocations stay as the draw recorded them.
- `lastAssignees` lets a later `replaced` event clear the owner.
- `planSplitMonth` refuses an empty id list (`empty-list`, with UI text); otherwise a sheet with no detected id column would move every unstudied case.
- The split report download runs after the success notice, so a download error no longer reads as a failed split.
- A failure on a later import reports the cases already moved (`moved`), and not-found ids are counted (`skipped`).
- `assignUndistributedCases` validates the employee against the roster, and its read-then-append race is documented (admin-only).

**Not changed (noted):** the split's studied check still runs before the lock. Its window is the time between the preview and the click. The settings sections keep the existing `view-error-log` admin gate that their siblings use.

**Why:** A pre-merge review of PR #231 found that v159.3's `""` («غير محددة») L1/L2 result leaked into counting readers. `classifyImageResult` maps anything that is not «اشتباه» to «سليمة», so the population/port report fold and the prior-month suspicion rate counted result-less Excel cases as clean. ## v158.0 — 2026-11-07 — Add (engine): catalog and slide picks

**Why:** Departments choose report slides by number («1، 4، 5، 6») instead of describing layouts to an admin, so the engine needs a numbered, named catalog of slide designs, a way to turn picks into a report spec, and a way to see the designs before choosing. Rejected: free-text slide descriptions (not deterministic, M16), and renumbering designs when one changes (a number a department already sent must keep meaning the same slide).

**What changed:** Milestone 5 of the report engine, all under src/engine/catalog/ except where noted.
- Catalog: nine active designs from deck3 (1 section divider, 2 KPI row, 3 bars, 4 detail table, 5 KPI plus bars, 6 bars with note, 7 top ranked, 8 KPI plus table, 9 glossary) and planned designs 10 to 17, with human Arabic names (M15) and a locked number list (numbers.lock.ts).
- picks.ts: parsePicksText and parsePicksSheet; retired, unknown, repeated and planned numbers are refused with Arabic messages.
- bind.ts: buildSpecFromPicks binds each pick's slots (field, measure or text) into a PageSpec and collects every issue before refusing; a title with no figure is refused unless the design waives R8.
- lookbook.ts: renderLookbook, a static page of every design with a labelled demo slide («بيانات توضيحية», F3), optionally previewing the real files.
- issueFromPicks.ts (this task): thin composition, parse then bind then issueReport; any refusal returns ok:false with the issues and no files (M13). The recipe stores the bound ReportSpec, so reissueFromRecipe works unchanged and the recipe schema is not bumped.
- index.ts exports CATALOG, activeDesigns, getDesign, the picks parsers, buildSpecFromPicks, renderLookbook and issueFromPicks with their types.
- Core changes made along the way: lint gained a catalog entry gate with F5 and per-design overrules; the issue pipeline resolves figures in page titles; pages accept titleRow:false.
Rulings:
- Message keys use the existing dotted style (catalog.unknownNumber, picks.repeated, bind.missingSlot).
- Page titles resolve {{measure:}} figures (reserved visual id "title"); bind requires a figure in a title.
- VisualSpec.limit is applied: with others:false the totals are on the kept rows, and the "~top" totals exist in the engine only, not as Excel formulas.
- F5 (a good/bad tone needs a status word in text) blocks issue, not only catalog entry.
- Planned designs freeze their number and name; their slots freeze when the design is activated.
- titleRow:false is used for section dividers.
- pageNote repeats on continuation slides of a long table.

**Migration/rollback:** No data format change: the recipe schema is unchanged and recipes issued before this version re-issue as before, except that a recipe issued before v158.0 whose spec has a `limit` now re-issues with that limit applied, so it is not byte-identical. Rollback: revert the branch claude/report-engine-catalog; nothing outside src/engine, docs and package.json changed behaviour.
