## v59.165 — 2026-08-04 — Fix (user-management): skip redundant activity/actions re-fetch on section switch-back

**What changed:** `UserManagementTab` never unmounts across its own internal `section` switches (users/page-permissions/feature-permissions/activity/actions — one component instance, local state), so the `"activity"` and `"actions"` data-loading effects re-fetched from disk every time the user switched back to a previously-loaded section, even though nothing had changed. Added two skip-guard refs (`activityLoadedForRef`, `actionsLoadedForRef`) remembering which `directoryHandle` each section was last successfully loaded for; the automatic effect-triggered fetch is now skipped on a plain switch-back, and still fires correctly on first visit or a genuine workspace change. The manual "تحديث" refresh buttons are untouched and still re-fetch unconditionally on every click. Part of the architecture-evaluation P1 backlog, item 3 — implemented via `docs/superpowers/plans/2026-08-03-p1-mount-preservation-holdouts.md`, Task 1.

## v59.164 — 2026-08-04 — Fix (reports): stop rebuilding the KPI model on every switch back to the dashboard

**What changed:** The KPI dashboard's model-building effect nulled the built `model` and rebuilt it from scratch (the heaviest read path in this tab: population + sample + all employee files + template + distribution) every time the user switched the section away from `"kpi"` and back — even when `directoryHandle`/`selectedMonth` never changed. Added a `kpiModelBuiltForRef` tracking which `(directoryHandle, month)` pair the current model was actually built for; the effect now skips the rebuild when returning to `"kpi"` for the same pair, and still rebuilds correctly on a genuine month/workspace change or after a prior build failure (whose ref is left unset, so it auto-retries). Part of the architecture-evaluation P1 backlog, item 3 — implemented via `docs/superpowers/plans/2026-08-03-p1-mount-preservation-holdouts.md`, Task 2.

## v59.163 — 2026-08-04 — Fix (auth): gate authenticated render on usersHydrated instead of a deferred clear

**What changed:** `AuthGate` rendered `AdminToolbar` + the full authenticated app tree as soon as `session` was truthy — including a session restored from `sessionStorage` on page load — before `WorkspaceContext` confirmed (`usersHydrated`) that the workspace's real disk-synced user list had actually been synced in. A deferred effect already re-validated and cleared a stale session once `usersHydrated` caught up, but for the brief window in between, a since-revoked identity's UI (role-preview switch, logout, feedback toggle) was visible before being yanked away. `WorkspaceGate.tsx` already solves the identical race one layer down with the condition `status === "ready" && !usersHydrated` plus a spinner; this applies the same condition at the `AuthGate` level, reusing the existing shared `LoadingState` component. Bounded to `workspaceStatus === "ready"` specifically (not bare `!usersHydrated`), so a session with no workspace ever connected is never stuck behind the gate. Exempt sessions (bootstrap admin, demo) are never gated, since they're never subject to the deferred re-validation this protects. Part of the architecture-evaluation P1 backlog (`docs/superpowers/specs/2026-08-03-reference-architecture-evaluation.md`, item 4) — implemented via `docs/superpowers/plans/2026-08-03-p1-mount-preservation-holdouts.md`, Task 3.
