## v59.103 — 2026-07-30 — Fix (reporting): a failed report/deck build left an already-opened export tab permanently blank

Owner reported the executive report card's "التصدير" button opening a blank/broken tab.
Systematic root-cause investigation (not a fix-by-guessing pass): live reproduction was blocked —
the app requires a real workspace folder via the File System Access API's native OS directory
picker, which isn't scriptable from this session's browser automation — so the investigation went
through the code history instead. `docs/edit logs/2026-07-21.md`'s v56.12 entry documented the same
symptom class once before ("a real mechanism for a permanently blank opened tab"), caused back then
by a blob-URL revoke race in `openOrDownload()`. That was fixed by switching to the current
`openReportWindow()`/`writeReportToWindow()` pair (open a blank same-origin window synchronously,
`document.write` into it once the HTML is ready — no blob URL, no race).

The 2026-07-29 P3-7 rework (`docs/audit/FULL_SYSTEM_AUDIT_2026-07-29.md`) then made all 5 report/deck
builders async, chunked with `await yieldToMain()` breaks so large exports don't block the main
thread, and re-pointed every `openXxx` wrapper to call `openReportWindow()` before the build's first
`await`, matching this same "open early" pattern. That rework reintroduced the exact same failure
class through a different door: every `openXxx` function now does `const reportWindow =
openReportWindow(); const html = await buildXxx(...); writeReportToWindow(reportWindow, html, ...)` —
if the now-async `buildXxx(...)` throws for any reason, `writeReportToWindow` is never reached, so
the window opened moments earlier is abandoned open and blank, with only a generic "حدث خطأ أثناء
توليد التقرير" toast in the original tab (nothing connects that toast to the dangling blank tab, and
nothing closes it). Confirmed with a failing test first (`executive/index.test.ts`): mocking
`buildDocumentSlides` to throw showed the real `window.open` handle's `close()` was never called —
proof the window is left open, not merely that an error is thrown.

Fixed by adding `writeOrCloseOnFailure()` (`htmlReport.ts`): it wraps the awaited build in a
try/catch and closes the already-opened window before rethrowing, so a build failure once again
leaves no visible tab behind — matching the pre-P3-7 guarantee (build first, open only once HTML is
ready) while keeping the async/chunked build. All 7 `openXxx` call sites (`openExecutiveReport`,
`openExecutiveDeckV2`, `openSampleReport`, `openSampleDeck`, `openDistributionDocument`,
`openDistributionDeck`, `openManagementDeck`) now route through it. This does not address why any
particular build might throw for the owner's real data — only the class of gap where a build failure
of any origin abandons a blank tab; if the underlying build-time error recurs, the browser console
(F12) will now show it against a closed tab instead of a lingering blank one, which is where the next
investigation step would start.

```ts
/**
 * Runs `buildHtml` and writes its result into `reportWindow` (opened earlier
 * via `openReportWindow`, before the build's first `await` — P3-7's "open
 * early, write once ready" pattern). If `buildHtml` throws, the window it was
 * meant to fill in would otherwise sit open and permanently blank — the write
 * only happens on the success path below, and nothing else ever touches
 * `reportWindow` on a failure. Closing it here instead re-establishes the
 * pre-P3-7 guarantee (a failed build never leaves a visible tab behind) while
 * keeping the async/chunked, main-thread-friendly build. Rethrows so the
 * caller's existing error-toast handling still fires unchanged.
 */
export async function writeOrCloseOnFailure(
  reportWindow: Window | null,
  buildHtml: () => Promise<string>,
  filename: string,
): Promise<void> {
  let html: string;
  try {
    html = await buildHtml();
  } catch (err) {
    if (reportWindow) {
      try {
        reportWindow.close();
      } catch {
        // Ignore; nothing more we can do if the browser refuses to close it.
      }
    }
    throw err;
  }
  writeReportToWindow(reportWindow, html, filename);
}
```
