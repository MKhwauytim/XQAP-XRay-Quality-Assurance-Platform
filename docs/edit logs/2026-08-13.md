## v70.14 — 2026-08-13 — Fix (bulk-reassign): record bulk reassignment in the action log and route it for approval when the actor cannot approve

**Why:** Reported from the app: the oversight bulk-reassign bar in صور الأشعة المحالة "doesn't log the
request or send it to supervisor for approval". Both were true. `handleBulkReassignConfirm` called
`executeBulkReassignment` directly, which appends `reassigned` events to the distribution log and stops
there — no `5-system/audit/actions.log.json` entry (unlike the Population tab's bulk assignment, which
writes `distribution-bulk-assigned`), and no path to `ew/referral-approval` at all. The bar is gated on the
`bulk-reassign-referrals` feature permission, which is independently editable per role: granting it to a
role that cannot approve referrals handed that role a silent, unreviewed, unlogged way to move any number
of other people's samples.

**What changed:** The action now follows the same rule the rest of the app already uses — the actor's own
authority decides whether it applies immediately or is routed for review, and the governance-relevant
outcome is recorded either way.

- Holding `approve-referrals` (supervisor/manager by default) keeps the existing immediate apply, since
  that permission *is* what the approval step would ask for; requiring self-approval would be a no-op round
  trip. This mirrors `employee-reopen-instant` in the self-service reopen flow. It now also writes a
  `distribution-bulk-reassigned` audit entry (actor, role, target employee, sample count, skipped count,
  selected-vs-filtered source, reason) — the counterpart of `distribution-bulk-assigned`.
- Without `approve-referrals`, confirming creates ordinary **pending `ReferralRequest` records** instead
  of touching the distribution log, so the batch shows up in `ew/referral-approval` and is applied by the
  existing `approveReferral` when a supervisor approves it. New module
  `src/data/referral/bulkReassignRequest.ts`. A `ReferralRequest` carries exactly one `fromEmployee` (its
  record lives in that employee's answers file and `approveReferral` validates ownership against it), while
  a bulk selection can span many current owners — so eligible rows are grouped by current owner and one
  independently-approvable request is created per group. Request ids are derived from the modal's existing
  `sourceRequestId` plus the sorted owner name, and `appendReferralRequest` de-duplicates by id, so
  re-confirming after a partial failure creates nothing new. Submission is logged as
  `distribution-bulk-reassign-requested`.
- The dialog states which of the two outcomes the click produces *before* it happens (summary sentence,
  confirmation checkbox and submit button all switch wording), including a note when the batch will be
  split into several per-employee requests.

Both new action types are rendered in the User Management → الإجراءات audit view via new label keys.

## v70.13 — 2026-08-13 — Fix (adhoc-import): clamp the file input so it cannot overflow a narrow viewport

**Why:** Found by Level 4 live verification, not by the static audit — the built `dist/index.html` was
driven in Chromium across five viewport widths after walking every tab and clicking ~110 controls.

At 320px the page reported `scrollWidth=392` against `clientWidth=320`: a 72px horizontal overflow.
The v70.11 panel clamps had already fixed the feedback panel, so this was a second, independent source.
Measuring every element wider than the viewport named exactly one: the `<input type="file">` in
`.adhoc-import-upload-card`, computed `width: 343px`, `left: -72`.

A file input sizes itself to its content (the browser's button chrome plus the filename text), and as a
flex item with the default `min-width: auto` it refuses to shrink below that intrinsic size — so it hung
72px off the start edge with no way to reach it.

**What changed:** `max-width: 100%` and `min-width: 0` on the file input, the same clamp pattern applied to
the overlay panels in v70.11. Re-measured in Chromium after the fix: `scrollWidth=320`, zero elements
exceeding the viewport, and no horizontal overflow at 1440, 1024, 768, 390 or 320.

## v70.11 — 2026-08-13 — Fix (ui/a11y): clamp overlay panels, add focus traps and accessible names, fix AA contrast, replace native dialogs

**Why:** A Level 2 UI/UX audit raised 45 candidate findings; each was independently verified against the
real code by two reviewers, and only the 26 both accepted were applied. The rejected 19 were dropped either
as not-real or as not worth the churn — notably a claim that the whole `primitives.css` button/card system
was dead code and should be deleted. Both reviewers re-ran that grep and found `StateViews.tsx` uses
`ui-state` across 13 sites; acting on it would have stripped the styling off nearly every data view.

The accepted items, grouped:

1. **Overlay panels had fixed pixel widths with no viewport clamp.** `.fb-panel` (380px), `.gms-popover`
   (280px) and `.ew-col-panel` (320px). The feedback panel was confirmed in a real browser at 320px and
   390px viewports: `width=380 left=24 right=404`, i.e. 84px past the viewport — and because it is
   `position: fixed`, `body { overflow-x: hidden }` neither clipped it nor created a scrollbar
   (`scrollWidth` stayed 320), so the cut-off part was unreachable by any means. `FeedbackWidget.css` has
   no media queries at all. `.confirm-dialog` likewise had no `max-height`, so a long message on a short
   viewport pushed its action buttons off-screen with no scroll.
2. **Two modals declared `role="dialog" aria-modal="true"` with none of the behaviour.** `ModalPortal`'s own
   doc comment states callers must wire `useFocusTrap` themselves; `MappingSettingsModal` and
   `DeckDesignCustomizer` never did — no initial focus, no Tab containment, no Escape, no focus restore.
3. **`--c-sky` (#009ADE) fails WCAG AA as small text.** Re-derived independently: relative luminance
   0.2842, contrast vs white 1.05/0.3342 = **3.14:1**, against the 4.5:1 requirement for text under
   18.66px. `--c-sky-2` (#007FBA) is 4.43:1 and also fails.
4. **Missing accessible names.** The manual-distribution search `<label>` wrapped only an `aria-hidden`
   icon, so it contributed no text; `DataTable`'s and `DataAccuracyReport`'s search inputs relied on
   `placeholder`, which disappears on type. `DataTable`'s `<th>` carried no `scope`.
5. **Native browser dialogs in an RTL Arabic app.** `ConfirmDialog`'s own doc comment says it exists to
   replace `window.confirm` (LTR, browser-chrome buttons); the storage reset and the ad-hoc import close
   were the last two holdouts, and a failed export used `window.alert`.
6. **A double-submit window.** `InspectionPanel`'s submit button stayed enabled during the async disk
   write, so a double-click fired `onSave` twice concurrently — while every other mutating action in the
   app tracks a busy flag.
7. **Hard-coded Arabic in shared chrome** that admins cannot customise, including three independent copies
   of the `app_tab_loading` string.
8. **The B4 hex-literal guard only ever covered 4 CSS files**, so CI stayed green while ~800 un-tokenized
   literals accumulated in the other 26.

**What changed:**

- **Clamps** — `width: min(Npx, calc(100vw - 32px))` on the three panels; `max-height` + `overflow-y: auto`
  on `.confirm-dialog`. Re-measured in the browser after the fix: 288px at a 320px viewport, 358px at 390px,
  both fully inside the viewport.
- **Focus traps** — `useFocusTrap` on both modals. `MappingSettingsModal` passes `enabled: isOpen` because
  the hook sits above its early return. Deliberately no backdrop-click-to-close on it: it edits mapping
  settings and a stray click would discard input.
- **Contrast** — added `--c-sky-text: #00719F` (5.43:1, verified) rather than mutating `--c-sky-2`, and
  repointed only the three *live* small-text uses: `.rh-eyebrow`, `.dt-filter-head button`,
  `.page-header-eyebrow`. `--c-sky` is untouched for icons/borders/fills, which need only 3:1.
  `.population-eyebrow` and `.ui-section__eyebrow` were confirmed to have zero TSX users and left alone.
- **A11y** — `aria-label` on three search inputs; `scope="col"` on the shared `DataTable` header.
- **Dialogs** — storage reset and ad-hoc import close now use `ConfirmDialog`; the export failure renders an
  in-page `role="alert"` banner. Reopening a closed batch needs no confirmation, so only the close path
  prompts.
- **Double-submit** — a `submitting` flag gates `submitStudy`, disables the button and swaps its label, and
  always clears in a `finally` so a rejected save cannot leave the button stuck.
- **Labels** — new keys for the crash screen, access-denied page, data-view defaults, confirm defaults and
  the inspection form. `StateViews` now defaults to the existing `app_tab_loading` instead of a second copy
  of the same string, and `InspectionPanel` reuses the existing `rd_bool_yes`/`rd_bool_no`. The
  ErrorBoundary's raw exception text is now wrapped in `<bdi dir="ltr">` so an English message cannot
  visually scramble inside the RTL card.
- **Hex guard** — baseline extended from 4 files to 30 (excluding `src/index.css`, which is where the tokens
  are *defined*), each pinned at its current count as a ratchet. `EmployeeWorkspace.css` was ratcheted down
  10 → 7 to match reality. This is explicitly not a claim that those files are clean — only that the drift

Caught during this change: moving the reset confirmation into the button's `onClick` initially bypassed the

## v70.10 — 2026-08-13 — Fix (population/sampling): guard foreign sub-tab events, thread stage mappings into replacement appends, and report true Excel row numbers

**Why:** Three independent defects surfaced by a full-codebase audit, each confirmed against the code and
each previously uncovered by the suite:

1. `Sidebar.tsx` dispatches the generic `pop-set-subtab` event on `window` for *every* tab's sub-tab clicks,
   and `App.tsx`'s tab-mount LRU keeps up to 3 tabs mounted (hidden, not unmounted). Population's listener
   therefore stayed live while another tab was active and accepted foreign ids: clicking Reports' `kpi`
   sub-tab set Population's `activeSubTab` to `"kpi"`, a value outside its own `SubTab` union. The render
   then hides Browse *and* returns `null` for Process simultaneously, so the tab goes blank. Its three
   sibling tabs (EmployeeWorkspace, Reports, UserManagement) all already guard against a known set;
   Population was the only one that did not.
2. `appendSampleRow` classified a replacement row with `getStageKey(row.stage)` and no mappings, silently
   falling back to `DEFAULT_STAGE_MAPPINGS` — while the draw path and `getReplacementCandidates` both thread
   the workspace's configured aliases. In a workspace using custom stage aliases the replacement row hit the
   `if (stageKey === "unknown") return allocations;` guard and was dropped from `stageAllocations`. The row
   still landed in `rows[]` and distributed and answered normally, so nothing failed loudly, but
   `actualDrawn` / `certScanDrawn` / `nonCertScanDrawn` permanently under-counted by one per replacement —
   and those fields feed `sampleReport.ts`, `executiveKpiProfiles.ts` and the executive deck.
3. `worksheetToSourceRows` passed `blankrows: false` to `sheet_to_json`, which drops fully blank rows before
   the mapping runs, then derived `sourceRowNumber` as `index + 1` over that compacted array. Every interior
   blank row shifted the reported number of everything below it. That number is user-facing: it is rendered
   as «رقم الصف المصدر» in the dropped-rows diagnostic, i.e. the pointer a user follows back into their
   spreadsheet to fix an invalid or duplicate X-ray ID. Blank spacer rows are common in hand-maintained
   agency exports, so users were being sent to the wrong line — or a blank one.

**What changed:**

- **Population sub-tab guard** — added `KNOWN_POPULATION_SUB_TABS` and a membership check in the
  `pop-set-subtab` handler, mirroring the pattern already proven in the three sibling tabs. The legacy event
  is deliberately left in place; migrating to `sidebar-subtab-changed` is a separate behavioural change
  (both `Sidebar.tsx` and `WorkspaceGate.tsx` still fire the legacy event).
- **Stage mappings threading** — `appendSampleRow` and `incrementStageAllocations` take an optional
  `stageMappings`; `executeReplacement` accepts and forwards it. `XrayReferrals.tsx` passes the mappings it
  already holds in state. `approveReferral.ts` resolves them via `loadPopulationConfig`, best-effort: a
  config-load failure falls back to `undefined` (today's behaviour) rather than failing an otherwise valid
  approval. Omitting the parameter preserves current behaviour at every other call site.
- **True Excel row numbers** — `blankrows: true`, so array position tracks the worksheet row before
  anything is dropped. The existing `isNonEmptyRow` filter still discards the now-visible blank rows, after
  the index has been captured, so header derivation, `validColumnIndexes` and the double filter all behave
  identically. Clean sheets produce byte-identical output.

Deliberately **not** changed: `incrementStageAllocations`'s new-entry branch still labels the bucket from
`row.stage`, and no `SAMPLING_ALGORITHM_VERSION` bump — this fixes a derived counter on future writes only,
invalidating no historical draw.
