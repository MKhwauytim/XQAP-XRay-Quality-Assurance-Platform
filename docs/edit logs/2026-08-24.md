## v120.2 — 2026-08-24 — Fix (feedback): pin the clock in two same-millisecond-tie-flaky newest-first ordering tests

**What changed:** `feedbackStorage.test.ts`'s "orders summaries newest-first by createdAt" (`listThreadSummaries`) and "returns every thread as a FeedbackMessage, newest-first" (`loadFeedback` aggregate) tests each create two threads back-to-back via `createThread`, which stamps `timestamp: new Date().toISOString()`. Found during this day's final whole-repo gate sweep: both tests intermittently failed when run alongside the rest of the suite (not in isolation) because the two `createThread` calls can land in the same real-clock millisecond against the in-memory test backend, and `listThreadSummaries`'s stable sort (`b.createdAt.localeCompare(a.createdAt)`) then falls back to whatever order the two threads entered its reconciliation `Map` in — not necessarily creation order.
