# Edit Log — 2026-08-12

## v70.0 — 2026-08-12 — Change (perf): Slice A — stop blanking, stop readers writing, stamp-gated sync tick

**Why:** The app re-read workspace JSON from the (slow, UNC) share far more often than the data
changed, and two views blanked to a spinner while it happened — the owner's "keeps refreshing / feels
slow / unsynced" complaint. Root-caused to four independent mechanisms, only one of which was raw load
time: unconditional `setLoadState("loading")` on the periodic tick; a full reload as the sync mechanism;
*readers that write* (a read path fired an unawaited multi-MB cache write, so N machines opening a month
produced N large writes of byte-identical data); and warm-up product held in `useState`, which the 3-tab
LRU discards.

Rejected, after two adversarial review rounds (`docs/architecture/PERF_SYNC_ENHANCEMENT_2026-08-12.md`
§3.1): a 1 KB envelope-prefix change probe — `safeWrite.ts:228-252` streams `metadata` LAST (the content
hash over `data` must exist before metadata can be built), so a prefix probe reads no metadata at all for
the largest file in the app; and `revision` as a universal change signal — the read-path write above bumps
it on byte-identical data. What replaced them was already in-tree: `readDistributionLogStamp`, whose
revision comes from `appendDistributionEvents` and never from `saveDistributionCurrent`, making it
structurally immune to that false positive.

Also rejected: month-granular residency (some cross-month reads are small and deliberate), a per-month
`kpi.summary.json` on disk (its fingerprint omitted the inspection template — already a shipped bug once),
and A5's `userDisplayMap` memo (a render-time allocation with zero I/O benefit and a wrong-data risk).

**What changed:** Slice A of the perf/sync plan, in three disjoint file lanes.

*Stop blanking (A2, A10).* `useApprovalData.ts` and `NotificationManager.tsx` gained the `{ silent }`
option `XrayReferrals.tsx` already had; the refresh subscription passes it via an explicit lambda, because
`subscribeToDataRefresh(reload)` hands the callback the bare `DataRefreshSource` string as its first
argument — it would have landed in `opts` and silently defeated the silent refresh. `BrowseDataView` keeps
previously-loaded rows mounted under a dimmed overlay during a reload instead of unmounting the table.

*Stop readers writing (A6).* `loadOrDeriveDistributionCurrent` takes `{ persistCache }`; the two pure-read
call sites (orphan scan, Power BI export) and `...ForRead` pass `false`. The four write flows that append
distribution events — bulk assignment, referral approval, ad-hoc import assignment, reopen — now call
`refreshDistributionCacheAfterWrite` explicitly, because they previously relied on the next *reader* to
refresh both the cache and every employee sample mirror. A derive-and-persist gate on
`sampleRows.length > 0` closes a pre-existing hazard: a missing `sample.master.json` folded to
`entries: []`, which the read path then wrote as the cache, and the next reader's fast-path guard accepted
it as authoritative.

*Stamp-gated sync tick (A7).* New headless `SyncTick` computes a change set per family
(distribution via `readDistributionLogStamp`; notifications and manifest via revision; requests and
answers via sized directory listings) and broadcasts only on a real diff, pairing every non-empty change
set with `bumpWorkspaceEpoch`. Cadence 45 s plus a visibility-coalesced focus tick. `queryRefreshBridge`
narrowed from an unscoped `invalidateQueries()` to manual→full / periodic→per-family.

*Landing sub-tab (A1).* Population lands on `browse` only when `can("view-browse")` AND
(`draw-sample` OR `process-population`). Both clauses are load-bearing: without the first the user lands on
the unauthorized placeholder; without the second an employee pays a multi-MB read they pay nothing for
today, since `BrowseDataView` reads the whole population on mount with no already-loaded guard while
`computeMonthLoadScope` returns `population: false` for that viewer.

**Migration/rollback:** No on-disk format changes. Every item is independently revertable. The only
derived artifacts touched (`distribution.current.json`, `*.samples.json` mirrors) are rebuildable from the
immutable event log. Report/export snapshots verified byte-identical (`git diff --ignore-all-space` on
`*.snap` is empty), so the deterministic-by-contract surfaces are unchanged.

**Known-not-airtight, stated at each site in code:** A6's accepted regression — a month no manager has
opened re-derives per load — is bounded because the manager write path always persists. `safeWriteJson`'s
post-commit check is weaker for small files than large (`skipVerify` inverts at 512 KB), so a peer's valid
envelope can pass verification; that window is unchanged by this slice and is Phase 2's problem.

**Not covered:** the 3-6 hour distribution save. Its fix may already have shipped in v61.0 (192,063 -> 78
filesystem ops) but has never been run in a browser, and `bench-distribution.mjs` never calls
`saveDistributionCurrent` — the slowest half. Milestone 0's instrumentation is specified in the plan doc
and must be measured on the production share before Phases 1-4 are scoped.
