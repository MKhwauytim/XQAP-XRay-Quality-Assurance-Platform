# Edit Log — 2026-08-19

## v99.5 — 2026-08-19 — Fix (storage/pages-ui/distribution): retry SMB lock contention, route ad-hoc quality notes, and never persist a fold that absorbed events

**Why:** Three defects that all end the same way on a large, busy SMB workspace — assignment data quietly disappears, or the recovery the user is offered cannot work.

1. `NoModificationAllowedError` was classified as terminal permission loss. On a shared Windows/SMB folder that name means the entry is **locked by another writer** — another tab, or another machine mid-write — which is a timing condition, not a revoked grant. `casLoop` aborted on the first one and told the user "فقد الوصول إلى مجلد العمل — أعد الاتصال بمساحة العمل", whose only remedy (re-pick the folder) is powerless against someone else's open handle; `isTransientWriteError` likewise refused to retry it, so `safeWriteJson` failed a write that a 20 ms retry would have completed. This is the mirror image of the doctrine this repo already enforces on the read side: "could not read" is not "does not exist", and "could not write right now" is not "the workspace is gone".
2. Quality-note **writes** for an ad-hoc row were routed to the globally-selected month's answer store, while the **reads** on the same screen were already routed per row to `2-samples/adhoc-{importId}/`. In the month's store no item matches the ad-hoc `xrayImageId`, so `setItemQualityNote` took its idempotent no-op branch: the UI reported success, nothing was written, and the note vanished on the next load. Third recurrence of the "month-folder walkers forget the ad-hoc store" class.
3. The headline one. `foldDistributionEvents` absorbs every event whose `xrayImageId` is not in the sample-row set it is handed. That is right for a genuine orphan and catastrophic for a row set that was stale or partially read: the assignments those events carry are simply not in the fold — and the fold is what gets written to `distribution.current.json` **and** its fold-checkpoint sidecar. Once written, every machine trusts the cache and the checkpoint is accepted forever, so one bad read of `sample.master.json` became the permanent, silent deletion of assignments from an audit month. The empty-row case was already gated (A6d) and the incremental resume path already refused to advance (`absorbedAbsentRows`); the FULL refold against a *partial* row set was the remaining hole, and it is the one Phase 4's own cache write steers readers onto — that cache carries no checkpoint and no `eventSetId`, so the next reader always takes the full path.

**What changed:**

- **`transientFileErrors.ts` / `casLoop.ts` (the classification points, not the call sites).** New `isLockContentionError`; `isTransientWriteError` now includes it, so `retryTransientWrite` rides the existing backoff ladder. `casLoop`'s `isPermissionLostError` no longer lists it, so it falls through to the retry loop. `NotAllowedError` / `SecurityError` remain terminal. New code **XQ-IO-035** (+ Arabic label `err_io_035_file_locked`) so an exhausted lock reports "in use by another device or window — try again shortly" instead of XQ-IO-032, whose text asserts the opposite ("وليس بسبب تعارض مع مستخدم آخر").
- **`XrayInspectionResults.tsx`.** The quality-note save now resolves its folder with the existing `monthFolderForEntry(row.entry, selectedMonth)` — the same per-row helper `XrayReferrals` and `useApprovalData` already use — instead of passing `selectedMonth` blind.
- **Absent-row persistence guard (`distributionDerivation.ts` → `distributionLog.ts` → `distributionStorage.ts`).** The fold now also reports `absentRowImageIds` (already computed for its own log line; purely additive — `entries` is untouched). `loadOrDeriveDistributionCurrent`'s full refold consults it: on absorption it re-reads `sample.master.json` fresh and, for every absorbed id the master holds and has **not** retired, re-folds against caller-rows ∪ those rows. If that heals the absorption, the healed result is served and persisted; if the master cannot be read at all, or the absorption survives, the result is served **in memory only** — no cache, no checkpoint sidecar, no session derive memo. When the master agrees the row is gone (a true orphan, or a replacement-retired row a caller filtered out on purpose via `liveSampleRows`), behaviour is byte-identical to before.

**Deliberately not done — the fold's computed result is unchanged.** The guard decides only whether a result may be *persisted*; `foldDistributionEvents` and `deriveCurrentDistribution*` compute exactly what they computed before for a given `(events, sampleRows)`. The heal adds back only rows that are (a) referenced by an absorbed event, (b) present in the master and (c) not replacement-retired — the union, never the master wholesale — precisely so `runPowerBiExport` and the executive report data builder, which pass `liveSampleRows(sample)` on purpose, cannot have retired rows resurrected into their output.

**T-13 (`eventSetId` stamp on Phase 4's refresh) skipped, deliberately.** `useDistributionActions.refreshDistribution` writes its cache with `logRevision` and nothing else, so that cache is always rejected by the next reader. Stamping `eventSetId` there would make a previously-ignored cache authoritative for every existing workspace — a change to cache-validity semantics, at a call site that is *not* the one this guard sits on and that has no absent-row guard of its own. Left for its own reviewed change.

```ts
// casLoop.ts
function isPermissionLostError(error: unknown): boolean {
  const name = (error as { name?: string }).name;
  return name === "NotAllowedError" || name === "SecurityError";
}

// transientFileErrors.ts
export function isLockContentionError(error: unknown): boolean {
  return errorName(error) === "NoModificationAllowedError";
}
export function isTransientWriteError(error: unknown): boolean {
  return isNotFoundError(error) || isNotReadableError(error) || isLockContentionError(error);
}

// XrayInspectionResults.tsx — route by the ROW, not by the selected month
const result = await setItemQualityNote(
  directoryHandle, monthFolderForEntry(row.entry, selectedMonth),
  row.entry.assignedTo, row.entry.xrayImageId, note
);

// distributionStorage.ts — heal first, refuse second; never persist an absorbing fold
const folded = deriveCurrentDistributionWithFacts(log, sampleRows);
let derived = folded.current, quotaFacts = folded.quotaFacts, mayPersist = true;
if (folded.absentRowImageIds.size > 0) {
  const recheck = await recheckAbsentRowsAgainstMaster(
    directoryHandle, monthFolderName, log, sampleRows, folded.absentRowImageIds
  );
  if (recheck.outcome === "healed") {
    derived = recheck.current; quotaFacts = recheck.quotaFacts;
    mayPersist = recheck.stillAbsent.size === 0;
  } else if (recheck.outcome === "unverifiable") {
    mayPersist = false;
  }
}
if (mayPersist) setDeriveMemo(memoKey, withRevision);
if (persistCache && mayPersist) { /* saveDistributionCurrent(... withRevision) */ }
```
