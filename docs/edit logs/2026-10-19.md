## v156.0 — 2026-10-19 — Fix (distribution): damaged distribution.current.json rebuilds silently; deleted months stay deleted; admin delete-month tool

**Why:** The owner reported a persistent «تعذّرت قراءة النسخة الأصلية من الملف distribution.current.json» banner, and described the habit that likely caused it: create a test month (process, draw, distribute), then delete its `1-population/` and `2-samples/` folders by hand.

Two defects met:
1. **The cache read fell back to `.bak`, but nothing repaired the live file.** `distribution.current.json` is a rebuildable fold cache, yet its read used the `.bak`/`.tmp` sibling fallback. The admin boot repair deliberately never heals this file from a sibling (`SIBLING_HEAL_EXCLUDED_NAMES`). So a damaged live copy was served stale from `.bak` on every load, and the banner promising an admin repair recurred forever.
2. **Background writers recreated deleted months.**
   - `saveDistributionCurrent` (the derived-cache persist) and even the answer-event READ (`readAllAnswerEventsForMonth`) opened `2-samples/{month}/1-main/` with `create: true`.
   - So any window still showing a just-deleted month rebuilt the folder around a lone, possibly torn cache file.
   - Employees' unsent answers for a deleted month also stayed queued forever, behind a permanent warning.

The owner approved:
- **An admin delete-month tool.** Refusal when a month has answers was rejected in favour of an explicit acknowledgement, because test months are answered too.
- **A discard path for answers stuck in deleted months.**

**What changed:**
- **`distributionStorage.ts`.**
  - `loadDistributionCurrent` reads with `siblingFallback: false` (`CACHE_READ`): a damaged cache is a cache miss, refolded from the events and rewritten, with no banner.
  - `saveDistributionCurrent` writes through `existingDistributionDirForCache`, which never creates a missing `1-main/` except for a legacy month whose sample still lives under its population folder. A deleted month is skipped.
- **`answerStorage.ts`.** `readAllAnswerEventsForMonth` opens the month with `create: false` and returns `[]` when it is gone; a read no longer creates folders.
- **New `population/deleteMonth.ts`.** `assessMonthDeletion` reports whether the month is closed, its strict answer count (it throws rather than guess) and which folders exist. `deleteMonth` re-checks at delete time:
  - a closed month is refused;
  - more answers than the admin acknowledged is refused;
  - otherwise it removes the samples folder first, then the population folder, and invalidates the dir/lock/fold caches.
- **New `Settings/DeleteMonthSection.tsx`.** The admin-only flow is: pick a month, check it, tick the acknowledgement when it has answers, type the folder name, then confirm. It writes a new `month-deleted` audit action (with its label and group), invalidates the month list and broadcasts a refresh.
- **`answerLocalMirror.discardPendingAnswers`, plus a banner action.** When a send reports `folder-missing`, «تجاهل إجابات الأشهر المحذوفة» confirms, downloads a copy of every unsent answer, and only then removes that user's pending records for those months.

**Migration/rollback:**
- **No on-disk format change.** The only new value is the `month-deleted` action type in the audit log; older clients show such an entry with a generic label.
- **Deletion is irreversible except from a backup,** and the confirmation says so.
- **Rollback:** revert the commit. Damaged caches would again be served from `.bak` with the banner, and month folders would again be recreated by background writes.

## v155.0 — 2026-10-19 — Add (sampling): high-priority ports in the sample draw; port pickers list every known port before upload

**Why:** The owner asked for two things.
1. **High-priority ports in the sample draw:** take each level's sample from chosen ports first, and only when they cannot cover it draw the rest normally.
2. **Port lists before upload:** the CertScan-ports picker should list every port before the month's Excel is uploaded or processed, so ports can be toggled first. It used to derive its list only from the current month's risk file, so before upload it was empty.

The owner chose these behaviours explicitly:
- **Strict priority** was chosen over a weighted "boosted share", where every port would still contribute.
- **The CertScan split is kept**, not ignored.
- **Draw only:** distribution order to employees is unchanged.
- **Same PR** as the unsent-answers fix.

**What changed:**
- **Draw (`sampleAlgorithmInternals.ts`, `SAMPLING_ALGORITHM_VERSION` "1.2" → "1.3").**
  - With priority ports among a stage's rows, the stage takes up to its CertScan target from the priority ports' CertScan rows and up to the rest of the target from their non-CertScan rows. Each type is Hamilton-apportioned across the priority ports by that port's pool of the type.
  - The remainder is drawn from the other ports exactly the normal way: Hamilton by size, CertScan share by pool.
  - A stage still short is topped up from any remaining row, priority ports first.
  - The stage CertScan target computation was refactored into `stageCertTarget` + `portCertShares`. This replaces the twin `exactCertTarget` / `percentageCertTarget`, which recomputed the same stage-level count once per port.
  - The plain path is `drawPortGroup` over every stage row: the same steps and RNG calls as before.
- **Record.** `SampleMasterData.priorityPorts` and `PortAllocation.priority` are written only when set, so a draw without priority ports keeps its exact file shape.
- **Config.** `PopulationConfig.priorityPorts` is an optional field like `certScanPorts`. `normalizeCertScanPorts` was renamed `normalizePortList`, since it now serves both fields.
- **Known ports.** New `knownPorts.ts` derives every port seen in any month's `sample.master.json` (`portAllocations` for names and sizes, sampled rows for port types). It is read-only, so there is no new stored state. `mergeKnownPorts` adds them to this month's catalog.
  - Both pickers in processing settings (reachable before upload) use the merged list, and it is re-read on every opening.
  - `CertScanPortsModal` takes `texts` and `loading`, so the priority picker reuses it.
  - Phase 3 shows the active priority ports above the draw.

**Migration/rollback:**
- **No migration.** The changes are three optional, additive fields (`config.json` `priorityPorts`, `sample.master.json` `priorityPorts`, `PortAllocation.priority`), following the `certScanPorts` precedent. Older files read as "no priority" and are never rewritten.
- **Old draws stay replayable.** A "1.2" draw had no priority ports, and the no-priority path is identical, so it replays the same under "1.3".
- **Rollback.** Revert the commit. A `priorityPorts` saved in `config.json` is then ignored, and samples drawn under "1.3" keep their rows and version stamp.

## v154.4 — 2026-10-19 — Fix (answers): repair each cause of unsent answers — step timeouts, permission request, backup/import

**Why:** v154.3 made «إرسال الآن» say *why* answers stayed unsent. The owner asked for each cause to be repaired, where the app can repair it. The highest-impact gap: a share call that never settles left the replay pass pending forever. The pass then held the cross-tab Web Lock and the in-tab join for the page's lifetime, so every 30 s tick and every button press silently joined or skipped it, and nothing was ever logged. That matches "pressed it, nothing happened" on one PC.

**What changed:** Each cause, and what now handles it:
- **Hung share.** Every replay step (folder probe, strict pre-read, per-item write) is bounded by `REPLAY_STEP_TIMEOUT_MS` (45 s). A step past the bound is reported as the new `not-responding` reason and the pass finishes, which releases the lock. The abandoned call is not cancelled; a late landing is harmless (event identity, or the next pass's on-disk check).
- **Browser write permission.** «إرسال الآن» calls `ensureDirectoryPermission(…, "readwrite")` first. The click is the user gesture the request needs; a background pass cannot ask.
- **Closed month, missing or unreachable folder, unreadable segments.** These are deliberately not overridden. `blocked` now carries `{ count, months }`, so the message names the months. Unreadable months are logged once per month per session (`answers:pending-replay-unreadable`); they were previously never logged.
- **Machine-specific faults with no in-app repair.** New `unsentAnswersFile.ts`: «تنزيل نسخة» exports the signed-in user's pending records; «استيراد إجابات غير مرسلة», signed in as the same user on any PC, re-queues them in that browser's outbox and sends. It refuses other users' files. It keeps a record's identity; a legacy record gets a fresh id with `eventAt = lastSavedAt`, so a newer answer on disk still wins the fold.
- **Cleanup.** The blob-download code duplicated in `demoDebugReport.ts` and `StorageSection.tsx` moved to `src/utils/downloadFile.ts`.

Rollback: revert the commit. The export file is the only new format, and nothing reads it automatically.

## v154.3 — 2026-10-19 — Fix (answers): «إرسال الآن» reports why unsent answers did not land

**Why:** An employee reported 110 answers stuck behind «N إجابة محفوظة على هذا الجهاز ولم تصل إلى مجلد العمل المشترك بعد» while every other employee synced normally, and pressing «إرسال الآن» did visibly nothing. The button called the fire-and-forget `requestAnswerFlush`, which discards the replay summary — and when a pass was already running it only flagged a re-run. Every reason replay leaves an answer pending (month closed, read-only, month sample folder missing in the folder this browser opened, folder unreachable / permission lost, unreadable segments, a write error, another tab holding the replay lock) was invisible to the employee and, apart from write errors, never logged — so there was no way to diagnose one machine's stuck queue.

**What changed:** `PendingReplaySummary` now carries `blocked` (counts per `PendingReplayBlockReason`), `lastError` (the last write/probe error name, or the write's own error text) and `skipped` (lock held by another tab); the folder probe distinguishes a missing folder from an unreachable one. New `flushAnswersNow` in `answerOutbox.ts` runs one pass now and resolves with the summary. The banner moved to `XrayReferrals/PendingAnswersBanner.tsx`: the button disables and reads «جارٍ الإرسال…», says the share is not answering after 30 s, then shows one Arabic line per outcome (`sendNowResult.ts` → new `ew_answers_send_*` labels). No change to what is written or when — diagnostics and feedback only.
