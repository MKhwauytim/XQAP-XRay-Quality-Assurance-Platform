## v154.3 — 2026-10-19 — Fix (answers): «إرسال الآن» reports why unsent answers did not land

**Why:** An employee reported 110 answers stuck behind «N إجابة محفوظة على هذا الجهاز ولم تصل إلى مجلد العمل المشترك بعد» while every other employee synced normally, and pressing «إرسال الآن» did visibly nothing. The button called the fire-and-forget `requestAnswerFlush`, which discards the replay summary — and when a pass was already running it only flagged a re-run. Every reason replay leaves an answer pending (month closed, read-only, month sample folder missing in the folder this browser opened, folder unreachable / permission lost, unreadable segments, a write error, another tab holding the replay lock) was invisible to the employee and, apart from write errors, never logged — so there was no way to diagnose one machine's stuck queue.

**What changed:** `PendingReplaySummary` now carries `blocked` (counts per `PendingReplayBlockReason`), `lastError` (the last write/probe error name, or the write's own error text) and `skipped` (lock held by another tab); the folder probe distinguishes a missing folder from an unreachable one. New `flushAnswersNow` in `answerOutbox.ts` runs one pass now and resolves with the summary. The banner moved to `XrayReferrals/PendingAnswersBanner.tsx`: the button disables and reads «جارٍ الإرسال…», says the share is not answering after 30 s, then shows one Arabic line per outcome (`sendNowResult.ts` → new `ew_answers_send_*` labels). No change to what is written or when — diagnostics and feedback only.
