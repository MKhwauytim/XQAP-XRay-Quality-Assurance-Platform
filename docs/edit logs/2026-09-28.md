## v140.0 — 2026-09-28 — Fix (integrity): boot self-check no longer flags the deck-preference files in 6-templates as unrecoverable

**Why:** The admin boot self-check reported a healthy `executive-deck-edition.json` (and `deck2.style-choices.json`) as an unrecoverable template on every admin sign-in. `inspectAllTemplateFiles` treated every `*.json` in `6-templates` as a template except two hard-coded names (`templates.index.json`, `template.selection.json`); the deck-edition and deck2 style-choice preference files also live in that folder with no `templateId`/`fields`, so `classifyLive` misclassified them as `corrupt`, no sibling qualified for recovery, and `recoverTemplateFile` returned `unrecoverable`, which `bootIntegrityScan.ts` surfaced as a `needs-attention` finding.

**What changed:** `templateStorage.ts`, `templateSelectionStorage.ts`, `deckEditionPreference.ts` and `deck2/styleChoices.ts` now each export their own file-name constant (`TEMPLATES_INDEX_FILE`, `TEMPLATE_SELECTION_FILE`, `DECK_EDITION_PREFERENCE_FILE`, `DECK_STYLE_CHOICES_FILE`) instead of keeping it module-private. `templateFileRecovery.ts` imports all four into one lazily-built `isNonTemplateFile()` set and gains a new `TemplateCandidate` member, `{ kind: "not-a-template" }`, for readable JSON that has no `templateId` — distinct from `corrupt` (damaged/unreadable JSON), so it is never flagged and never fed to the repair path. `inspectAllTemplateFiles` filters directory entries through `isNonTemplateFile()` instead of two hard-coded string comparisons, and additionally drops any report whose `live.kind` is `"not-a-template"` before it reaches the boot scan.
