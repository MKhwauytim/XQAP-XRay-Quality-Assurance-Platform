# Edit Log — 2026-08-20

## v104.0 — 2026-08-20 — Add (reporting): three القسم 3 analytics pages — daily accuracy trend, outcome matrix, risk-engine agreement

**Why:** القسم 3 (التحاليل المتقدمة) of the executive deck read population/quality
outcomes but had no view of *when* accuracy happened, no consolidated four-cell
outcome breakdown, and no comparison against the customs risk engine's own
targeting — three questions an audit of this kind is expected to answer, and
all three were answerable from data the report already loads (`xrayEntryDate`,
`targetedByRiskEngine`, `reportNumber`) but never surfaced. A fourth page,
**أداء حسب حجم الأعمال** (workload vs. accuracy), was rebuilt into a
`barCell`-based `.deck-table` correlation view (a deviation strip appended
below its two land/sea tables) as part of the same pass — explicitly **NOT**
a scatter/bubble chart: a scatter was the 2026-07-25 design the owner
rejected ("this graph make no sense"), and the whole point of the rework was
to answer the page's question with the deck's existing table idiom instead of
reintroducing a chart. It is shipped **disabled by default**
(`SHOW_WORKLOAD_ACCURACY_SLIDE = false` in `workloadAccuracy.ts`) — the
four-variant fan-out it replaced didn't hold up under review and the
correlation replacement needs a sign-off round of its own before it renders in
a real report. Task 8 (this entry) is the closing task of
an 8-task plan: it is the first task where the dev-preview fixture carries real
`xrayEntryDate`/`targetedByRiskEngine`/`reportNumber` values, so it is also the
first time all three new pages render their **populated** branch instead of
their empty state — and, as flagged in the task brief up front, that surfaced
one real layout bug (below) that no amount of reading the code would have
caught, because the empty-state branch never exercises the chart's layout.

**What changed:**
- **New model fields** (`executiveReportTypes.ts`, `executiveReportData.ts`,
  `decisionFactTable.ts`): `ExecutiveReportRow.entryDay` (1–31 or `null`,
  derived via the new `entryDayOf()` in `model/entryDay.ts` from the already-
  normalized `xrayEntryDate` — no second date parser), `hasReport` (derived
  from `reportNumber`), and `targetedByRiskEngine` bridged straight through
  from the population row onto the report row.
- **New aggregate** (`model/aggregates.ts`, `model/reportModel.ts`): folds
  `model.factTable` (the `DecisionRecord[]` built by `buildDecisionRecords`,
  DECISION grain — not `model.rows`, which is IMAGE grain) by `entryDay` into
  `ReportModel.dailyTrend` — `days` (one entry
  per day that has at least one evaluable decision; a quiet day is *absent*,
  never zero-filled), plus `datedShare` and an `undated` bucket so a sparse
  month's dated coverage is visible as a headline, not silently assumed.
- **New chart primitive** (`ui/analyticsCharts.ts`): `timeSeriesBand()` — a
  day-of-month polyline chart where each series carries its own shaded
  statistical-control band (reusing `reviewerKpis.ts`'s already-tested
  `buildPChart`/`P_CHART_MIN_N`, not a second control-limit implementation), a
  `null` point ends a run without joining across the gap, and out-of-band
  points get a shape/stroke marker (not color-only). Paired, per the module's
  existing convention, with a visually-hidden `<table>` for assistive tech.
- **Three new القسم 3 pages** (`deck2/section3/`):
  - `dailyTrend.ts` — `slide-s3-daily-trend`: two `timeSeriesBand` series
    (دقة السليمة / دقة الاشتباه), the dated-share headline, a per-day n strip,
    and a caution line below an 80% dated-share threshold.
  - `outcomeMatrix.ts` — `slide-s3-outcome-matrix`: the four outcome classes
    (اشتباه صحيح/خاطئ/فائت, سليمة صحيحة) month-wide and per port, reading
    `model.errorAnalysis` unchanged (never re-derived). Paginates via a
    bespoke two-tier planner (`planOutcomeMatrixPages`) because page 1 carries
    the matrix + totals band above the ports table and continuation pages
    don't share that budget — `planPortPages` (built for a single uniform
    per-page row budget) didn't fit.
  - `riskEngineAgreement.ts` — `slide-s3-risk-engine`: `engineVerdictOf()`
    maps the free-text `targetedByRiskEngine` column to a سليمة/اشتباه
    verdict for a small recognized vocabulary; blank AND unrecognized values
    both map to `null` and are excluded from every rate — a blank is
    "we don't know", never "cleared". Reports recognized/unrecognized/blank
    coverage counts, engine-vs-المراجع agreement (the one comparison
    independent of المستوى الثاني's own definition), the المستوى الثاني
    disagreement set, and محضر-backed outcomes.

    numbering shift accordingly.

**Before** (`dailyTrend.ts`'s `DAILY_TREND_CSS`, the rule that shipped in the
earlier task against only the empty-state fixture):
```css
/* Chart figure fills the remaining space in the body. */
.v2-dt-layout figure{flex:1;min-height:0;}
```

**After:**
```css
/* Chart wrapper fills the remaining space in the body — measured live via
   report:static against a populated fixture (2026-08-20): the original rule
   here targeted the inner figure element (analyticsCharts.ts's timeSeriesBand
   wrapper), but that figure is a grandchild of this flex column, not a
   direct flex item of it — .v2-ts-wrap (a plain block div) is the actual
   flex item, so flex:1 on figure was a no-op and the chart rendered at its
   unconstrained intrinsic height (~487px), pushing the per-day n-strip and
   legend entirely past the slide's fixed 630px box. Targeting the real flex
   item — with min-height:0 so it can shrink below the SVG's own intrinsic
   size — lets flexbox allocate it only the space left after the share
   headline, n-strip, and legend, and the height:100% chain (.v2-ts-wrap to
   figure to svg) resolves against that now-definite height. */
.v2-dt-layout .v2-ts-wrap{flex:1;min-height:0;display:flex;}
.v2-dt-layout .v2-ts-wrap figure{flex:1;min-height:0;}
```
