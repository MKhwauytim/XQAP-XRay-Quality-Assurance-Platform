## v59.69 — 2026-07-28 — Fix (executive-deck): slide content silently clipped at any viewport narrower than the ~1120px design width — root cause of "most pages look bad, unfitted text/bad shapes"

User reported, after visually reviewing the actual report across all 4 design
variants: "most of it look bad unfitted text or bad shapes." Live DOM-geometry
auditing (screenshot compositing isn't available in this sandbox — see prior
entries — so this used `getBoundingClientRect`/`getComputedStyle` sweeps across
every slide × every variant panel, activating each panel exactly the way
`DECK_VARIANT_SCRIPT` does) found genuine, severe content overflow on the
majority of pages, but **only at viewport widths below ~1150px** — a full-width
desktop browser (1280px+) showed none of it, which is exactly why this shipped
undetected through the whole multi-day fan-out effort: every verification pass
across every batch used a full-size dev viewport.

**Root cause:** `.slide` (`deck/deckTheme.ts`, shared by both the v1 and v2
decks) was sized `width:min(1120px,100%); aspect-ratio:297/167; overflow:hidden`
— i.e. its HEIGHT was derived from its WIDTH. Every page's row-budget math
(`BASE_ROWS_PER_PAGE`, filler-row heights, `briefingRankPlan`'s density tiers,
per-card row caps, etc., across the whole deck) is calibrated in fixed pixels
against the ~630px of height the slide gets at its full 1120px design width.
Any container narrower than ~1150px (accounting for the side-nav's reserved
space) — an ordinary laptop-width browser window, or the admin design
customizer's iframe (sized by its own modal chrome, not guaranteed to hand the
deck a full 1120px) — shrunk the slide's WIDTH via `min(...,100%)`, and
`aspect-ratio` shrunk its HEIGHT to match, silently invalidating every one of
those pixel budgets. The mismatch between "the actual room" and "the room the
layout math assumes" then clipped invisibly via the slide's own
`overflow:hidden` — exactly "unfitted text or bad shapes" from the reader's
side, with no error, no console warning, nothing to catch in a unit test that
never renders at a real narrow width.

**Fix, four parts, discovered and verified incrementally against a live,
worktree-scoped dev server sweeping viewports from 830px through 1440px:**

1. **Decouple height from width.** `.slide` now gets a FIXED `height:630px`
   instead of `aspect-ratio:297/167` — the same ~630px the design was always
   calibrated against, now guaranteed regardless of how narrow the container
   gets. This alone fixed 15 of 17 overflow cases found in the first sweep (at
   1024px viewport width). Confirmed zero regression at full design width
   (1120x630, unchanged) and at 1440px+ (unaffected, width still caps at
   1120px).
2. **Two localized `min-height:0` grid-item fixes** for the 2 cases the height
   fix alone didn't cover — the classic CSS Grid "item won't shrink below its
   own content" trap (a grid item's default `min-height:auto` lets its content
   win over its track size, growing the WHOLE grid row past budget): a stage's
   card in the `slide-stage-port-sample`/`-population` 2×2 grid (also given
   `white-space:nowrap` + ellipsis on its port-name column — a long name
   wrapping to 2 lines was the actual trigger), and `slide-closing`'s two
   grid columns.
3. **A missing flex wrapper** on `slide-s3-quality`'s Ledger variant
   (`.v2-lg-quality`) — it was a plain `height:100%` block box, which does NOT
   shrink block-flow children to fit; its mandatory caveat strip (a sibling
   after the 2-table split) rendered a few px past the wrapper's own bottom
   edge. Given `display:flex;flex-direction:column;min-height:0` + the split
   given `flex:1 1 auto;min-height:0` — the exact pattern `.v2-lg-workload`
   already used correctly.
4. **Raised the "narrow/mobile" reflow breakpoint from max-width:820px to
   max-width:900px** (both `deck/deckTheme.ts` and all 5 occurrences in
   `deck2/theme.ts`, kept in lockstep) after finding a second, narrower danger
   zone: even with fix #1, a 2-column layout (port tables, stage grids, etc.)
   forced into ~784px of actual width wrapped text badly enough to overflow
   dramatically (measured up to 778px of clipped content on one page) — the
   existing breakpoint's job is to abandon the fixed-card layout for natural,
   unclipped flow at exactly this point, but 820px cut it too close; 900px
   gives real margin, verified clean from 830px up through the full design
   width with no gap at the new boundary. **Discovered a second bug while
   fixing this**: the earlier height fix (part 1) had removed `aspect-ratio`
   from the unqualified height calculation, but the narrow-mode media query
   still only reset `aspect-ratio`/`min-height` (not `height`) — so narrow
   viewports were stuck at the new fixed 630px instead of getting genuine
   natural-flow sizing. Both media queries now explicitly reset `height:auto`
   too.

**Verified via a live worktree-scoped dev server** (`npm run dev`,
`deck-preview.html`, `variantPreview` mode) sweeping 830 / 850 / 870 / 900 /
901 / 950 / 1024 / 1440 px viewport widths, activating every one of the 21
slides' every variant panel exactly as `DECK_VARIANT_SCRIPT` does and measuring
real geometry — zero overflow at every tested width, in both the v1 (legacy)
and v2 decks (the fixed-height rule lives in the shared base file both share).

**File:** `src/data/reporting/executive/deck/deckTheme.ts` — `.slide`'s
`aspect-ratio` replaced with a fixed `height:630px`; its narrow-mode override

**File:** `src/data/reporting/executive/deck2/theme.ts` — all 5

with the base file); `.slide.v2`'s narrow-mode override now also resets

port-name truncation; `.v2-closing-main`/`.v2-closing-side` gain
`min-height:0`.

**File:** `src/data/reporting/executive/deck2/section3/qualityImpact.ts` —
`.v2-lg-quality` changed from a plain `height:100%` block box to
`display:flex;flex-direction:column;min-height:0`, with its `.v2-lg-split`

## v59.68 — 2026-07-28 — Fix (build): `npm run typecheck` was a silent no-op; fixed it and the 6 real type errors it had been hiding

User reported the admin design-customizer button as broken and asked for a final
check-up before merging. Investigation found no defect in the button's own wiring
(traced `handleOpenCustomizer` → `DeckDesignCustomizer` → the deck-wide segmented
control → `saveDeckStyleChoices`; `DeckDesignCustomizer.test.tsx` already exercises
this end-to-end with real `fireEvent.click` calls, not mocked handlers). What WAS
broken, and far more serious: `dist/index.html` — the single self-contained file
this app is distributed as — was last built 2026-07-23, five days and the entire
deck2 three-system fan-out effort before this session. Anyone opening that stale
file would see none of this week's work, including every fix already made to this
exact button.

Running `npm run build` to regenerate it surfaced 6 real TypeScript errors that
had never been caught by any of this multi-day effort's dozens of `npm run
typecheck` runs — because **`npm run typecheck` (`tsc --noEmit`) was a silent
no-op**. The repo's root `tsconfig.json` is a "solution" file (`"files": []`,
only `references` to `tsconfig.app.json`/`tsconfig.node.json`) meant to be built
with `tsc -b`, the mode `npm run build` already used (`"build": "tsc -b && vite
build"`). Invoking bare `tsc --noEmit` against that root config lists **zero
files** and exits 0 immediately — confirmed directly (`npx tsc --noEmit
--listFiles` → 0 lines; `npx tsc -b --listFiles` → 1029). CI's `typecheck` job
(`.github/workflows/ci.yml`) has been gating on this same no-op. This is why 6
real errors — 2 genuine unused-parameter violations repeated across 4 near-clone
Ledger table functions, 1 real `CellTone`-vs-`BriefingTone` type mismatch, and 1
typo'd test-fixture field — shipped across several already-reviewed commits
without a single `tsc` invocation ever actually inspecting the code.

**Fix:** `typecheck` script changed from `tsc --noEmit` to `tsc -b` (identical
mode `build` already uses) — verified it now checks all 1029 files and would have
caught every error below. The 6 errors themselves:
- `fanoutCoverSep.test.ts`: a fixture passed `selectedInSample: true` to `popRow()`,
  a field `PreparedPopulationRow` doesn't have (it's derived during
  `buildReportModel`, not settable on the raw input row) — removed; the fixture's
  `sample: null` input meant it was never doing anything.
- `ledgerQualityTable`/`ledgerAccuracyTable` (`slides.ts`), `ledgerLevelTable`
  (`section3/levelAccuracy.ts`), `ledgerAgreementTable` (`section3/portAgreement.ts`):
  all 4 took a `variant: "land"|"sea"` parameter, copied from their `portTableCard`-based
  slot-0 siblings, but build on `ledgerPortCard` — which has no icon/variant-driven
  behavior at all, confirmed by reading its signature. Genuinely dead in all 4;
  removed the parameter and updated both call sites per function.
- `qualityImpact.ts`'s Briefing rank-row builder passed `LEVEL_TONE[s.level]`
  (typed `CellTone`, which includes `"neutral"` — needed elsewhere in the same
  file for `qualCell`'s tinted cells) as a `BriefingRankItem.tone` (typed
  `BriefingTone`, no `"neutral"`). Verified `LEVEL_TONE`'s 3 concrete values
  (عالي→green, متوسط→gold, منخفض→coral) are always within `BriefingTone`'s range —
  a real subset relationship the type system just couldn't see from the wider
  declared type — so a scoped `as BriefingTone` cast at this one call site is
  correct, not a mask; documented why in a code comment.

Rebuilt `dist/index.html` (gitignored, not itself a tracked change) once the
build was clean.
