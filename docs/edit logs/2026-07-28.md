## v59.67 — 2026-07-28 — Add (executive-deck/deck2): fan-out slide-cover and slide-sep-1/2/3 to Ledger/Briefing/Grid (last 2 pages of the three-system fan-out)

Closes the deck2 three-system fan-out effort: the 17-page fan-out merged 2026-07-27
(`243c9f6a`) deliberately left `slide-cover` uncovered (an oversight in the original
plan, not a ruling) and `slide-sep-1/2/3` explicitly un-fanned-out (the plan's §4
argued a variant would be a pure shell reskin, forbidden by spec §5). The user's
follow-up instruction — "revise all pages and work even on separator pages and cover
etc" — asked for both to be done for real. A fresh Opus design-advisor dispatch
(`docs/superpowers/specs/2026-07-28-deck2-fanout-cover-and-separators-plan.md`)
corrected the prior separator ruling on its own terms: `.v2-sep` is the variant BODY
being re-composed on every other page in this deck, not the shell (eyebrow/headline/
subhead/rail/foot) spec §5 actually firewalls, and the true cost is one builder
(`sectionSeparatorSlide`) rendering all three separators, not "3 pages × 3 selectors ×
2 themes" as originally costed. What still stands, as a hard constraint: no
statistics return to the divider — the owner's earlier strip decision is not
reversed, and differentiation here is typographic/structural grammar only, over the
four fields the page already has (`sectionNo`/`title`/`blurb`/`tone`).

**`slide-cover`** (has full `ReportModel` access, unlike the separators — governing
rule: it may state SCOPE — population/sample/coverage, "what this document covers" —
never FINDINGS; nothing on a cover is honestly rankable, so no `briefingRankList`
anywhere on this page):
- **Ledger** — hero (title+lockup kept, kicker+badge dropped) beside one
  `ledgerTableCard` of 7 rows (فترة الدراسة/تاريخ الإصدار/الإدارة/القسم/مجتمع
  الصور/حجم العيّنة/تغطية العيّنة), each with `ledgerIdx`; no totals row (nothing to
  sum) — a classification footnote row instead.
- **Briefing** — title first (a cover's title cannot be demoted below a statistic),
  then `briefingLede` (population total as the SCOPE figure, no `arc` — coverage is a
  different unit than the lede's count), then `briefingSupport` (sample total /
  coverage / classification — the 3rd chip absorbs the dropped badge).
- **Grid** — new `gridFieldCells` primitive (label/value cells for pages with real
  fields but no comparable numeric domain — a cover is one entity with 4 strings + 3
  figures in 3 different units, so `metricMatrix` would be dishonest here; no
  `gridPanel` wrapper either, since its light-theme rule paints a white card, a hard
  break on the always-dark cover). 8 cells, 4×2, no magnitude tint (the 3 figures
  share no denominator — a tint would be invented magnitude).

**`slide-sep-1/2/3`** (input set closed — no `model`, no new `opts` field added):
- **Ledger** — deliberately NO table (no data exists; a one-row table would be
  theatre). A ruled document opener: hairline rule, `ledgerIdx(sectionNo-1)` +
  eyebrow, a smaller `<h2>` (2rem, vs slot 0's 2.6rem — a heading not a poster),
  another rule, a hanging-label definition line (`التعريف: {blurb}`), closing rule.
- **Briefing** — the cleanest reuse in the whole fan-out: one `briefingLede` call,
  nothing else (no support strip — nothing to put in it; no rank list). Figure =
  section number, `tone` mapped explicitly (`cyan → blue`) rather than passed through
  raw — `BriefingTone` has no `cyan` and there is no `.v2-bf-lede-figure.cyan` CSS
  rule, which the design plan flagged as a real bug this mapping avoids introducing.
  Page-local CSS bumps the figure to divider scale (6.4rem) and restyles
  `.v2-bf-lede-basis` from its default bordered-pill look (wrong for a ~30-word
  blurb) to a plain paragraph.
- **Grid** — one full-width `gridPanel` wrapping `gridFieldCells` (section number +
  the blurb as a wide cell) — the section number appearing in both the panel's `sub`
  line and a cell is this deck's own Grid idiom (every Grid page prints a column's
  domain in the header and its value in a cell), not a duplication.

`slide-month-numbers` stays explicitly skipped (dormant, `SHOW_MONTH_NUMBERS_SLIDE =
false` short-circuits the call site — slots 1-3 would never render in production or
preview either way).

**Highest-risk item, verified live**: the cover is dark in BOTH light and dark theme
by deliberate pre-existing design. Every new Ledger/Briefing/Grid rule for the cover
carries a matching `body.theme-light .slide.v2-cover …` re-override back to the dark
treatment, mirroring the pattern already used by `.v2-cover-meta-item`/
`.v2-cover-meta-value`. Verified in a live worktree-scoped dev server
(`deck-preview.html`, `variantPreview` mode, port 5188) by toggling
`document.body.classList.add("theme-light")` inside the deck iframe and reading
`getComputedStyle` directly: cover background stayed `rgb(6,40,70)` (navy) with
every new slot's text remaining white/slate (never flipping to dark-on-dark or a
stray white card) in both themes. Also verified live: no vertical overflow on the
cover's 7-row Ledger table or any separator's Briefing slot at the longest blurb
(section 3's), the cyan→blue tone-mapping fix (`slide-sep-2`'s Briefing lede
computes class `v2-bf-lede-figure blue`, never `cyan`), and that no slot-0 vocabulary
(`.v2-sep-watermark`/`.v2-sep-badge`) leaked into the 3 new separator variants.
