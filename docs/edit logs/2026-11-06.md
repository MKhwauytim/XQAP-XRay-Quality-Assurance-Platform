# Edit Log — 2026-11-06

## v157.0 — 2026-11-06 — Add (engine): report engine core, milestone 1

**Why:** Milestone 1 of the report-engine core plan (`.superpowers/sdd/2026-11-05-report-engine-core/`) needed one entry point that turns a spec plus raw files into every output in one pass with no AI (M16), all or nothing (M13), and a recipe that re-issues the same bytes (decision 12). Tasks 1 to 13 built the stages; this task joins them and closes the milestone.

**What changed:**
- `src/engine/issue/issueReport.ts` (new): `issueReport(spec, files, params, env)` runs, in the C11 order, `mergePackMeasures` + `validateSpec` + `themeIssues`, `typeDataset` + `profileColumns` + `applySteps`, `resolveVisuals`, `layoutReport`, `planWorkbook` + `writeXlsx`, `renderHtml`, `writePptx`, `buildRecipe`, then `runGates` (which receives the report workbook, the required companion, the spec, the layout and the recipe). An issue now outputs six files: HTML, the printable PDF route (`pdfPrintable` is the HTML string; the PDF is browser print), PPTX, the report workbook, the companion raw workbook (owner decision 2026-11-06) and the recipe JSON. Any issue from any stage (including `LayoutDoc.issues` and any theme issue), any throw, or any failed gate returns `ok: false` with no files and one Arabic message from `formatIssue(issues[0], params.messages)`, which names the page, visual and rule; long dashes quoted from content are replaced in the message. A throw in a writer stage maps to `gate.ooxml`, elsewhere to `schema.invalid`, with the stage in `detail`. Elapsed time is checked between stages against `LIMITS.issueTimeBudgetMs` (provisional) with `env.now` (default `performance.now`) and never enters an output.
- `reissueFromRecipe(recipeText, files, env)`: `validateRecipe`, `checkSources` (a changed or missing file gives `recipe.hashMismatch` naming it), then `issueReport(recipe.spec, files, recipe.params)`. Everything derives from `recipe.spec` and `recipe.params`; the copied columns, steps and measures are ignored, so a divergent copy cannot change the output (tested).
- The spec sketch passes a `packId`; the core instead takes the optional `DomainPack` in `env.pack`, because it never reads host storage. Re-issue does not merge a pack again: the recipe spec is already merged (C23).
- `env.__testSeam` ("miscountStep", "throwInPptx") is test-only and never set by a host.
- `src/engine/actions.ts`: `ENGINE_ACTION_MAP` (author: `validateSpec`; run: `issueReport` and `reissueFromRecipe`; view: `validateRecipe`) (C4).
- `src/engine/index.ts`: exports `issueReport`, `reissueFromRecipe`, `createFixedAdvanceMeasurer`, `ENGINE_ACTION_MAP`, `validateSpec`, `validateRecipe`, `mergePackMeasures` and the public types.
- Recipe is built before the gates rather than after, because `runGates` scans it (Task 12 ruling).

Deferred, from the controller ledger: F5, the Reflex and Finish lint passes (only the F1 token-pair contrast check ships); slicers; charts in the workbook; buttons and logo; the browser (canvas) text measurer (tests use the fixed-advance one); fixing `LIMITS` by measurement (all still provisional, Milestone 3); the trailing all-blank upload rows case, which can cause a false `gate.reconcile` block (fails closed, never a silent pass; Milestone 3). Real PowerPoint and Excel verification stays a manual release check until Milestone 3.

**Migration/rollback:** None needed. The engine is a new, isolated module under `src/engine/`; nothing in the app imports it yet, it changes no workspace file format and writes no host files. The bundle is unchanged by it for that reason (no measured cost claimed). Rollback: delete `src/engine/` and revert the engine commits on `claude/pptx-poc` (and the `package.json` dependency move made earlier in the milestone).
