# Edit Log — 2026-11-06

## v157.0 — 2026-11-06 — Add (engine): report engine core, milestone 1

**Why:** Milestone 1 of the report-engine core plan (`.superpowers/sdd/2026-11-05-report-engine-core/`, spec `docs/superpowers/specs/2026-11-01-report-engine-design.md`) needed a deterministic engine that turns a report spec plus raw Excel files into every output in one pass with no AI (M16), all or nothing (M13), with every figure traceable to the data and a recipe that re-issues the same bytes (decision 12). This one entry covers the whole milestone (tasks 1 to 14 and the final whole-branch review fixes), since branch base `8c6950e8`.

**What changed:**
- Foundations (`src/engine/errors.ts`, `messages.ts`, `limits.ts`, `version.ts`, `actions.ts`, `index.ts`, `boundary.test.ts`): typed `EngineIssue` rules with one Arabic message per rule, provisional `LIMITS`, the public entry points and `ENGINE_ACTION_MAP` (C4), and a boundary test that keeps the engine free of app imports.
- Data (`src/engine/data/`): `typeDataset` types raw cells per declared column and records type errors; `profileColumns`; `applySteps` runs filter, dedupe and calc steps with per-step in/removed/out counts (M12).
- Formula (`src/engine/formula/`): a hand-written, allow-listed formula parser and evaluator (hostile input refused), measure cycles detected, and `toExcel` translation for the workbook.
- Spec (`src/engine/spec/`): spec and pack shapes, well schemas, `validateSpec` and `mergePackMeasures` (C23).
- Resolve (`src/engine/resolve/`): `resolveVisuals` groups on typed identity, re-evaluates totals rather than summing cells, buckets chart overflow into «أخرى», and gives every value a key and provenance.
- Layout (`src/engine/layout/`): 24x14 grid layout with a fit ladder (never below 20px), bidi runs, continued «(يتبع)» table slides, figures and non-figure spans for parity.
- Writers (`src/engine/html/`, `pptx/`, `xlsx/`, `xml/`): self-contained HTML (PDF by print), PPTX via pptxgenjs plus a deterministic postprocess, and a report workbook with Arabic-named tables and pivots plus a companion raw-data workbook it links to (owner decision 2026-11-06).
- Gates (`src/engine/gates/`, `lint/`): OOXML self-check, read-back of all outputs, three-way layout parity, located figure parity, row reconciliation from raw rows through each step to the processed table (M12), and design lint (T3 long dashes, T6 symbols, F1 contrast, F4 font floor, M6 static digits as warnings).
- Recipe and issue (`src/engine/recipe/`, `issue/`): `buildRecipe`/`validateRecipe`, `issueReport(spec, files, params, env)` producing six files (HTML, printable route, PPTX, report workbook, companion workbook, recipe), and `reissueFromRecipe` refusing a changed raw file with `recipe.hashMismatch`.
- Final review fixes (this round):
  - A page or visual filter, or a well field, on another dataset's column was silently dropped and an unfiltered figure shipped. `validateSpec` now requires each to belong to the dataset of the visual's measures (`schema.invalid`), and `resolveVisuals` fails closed as a second guard. Report-level filters still apply only where their column exists.
  - Figure parity no longer blocks falsely when a `{{param}}` value shares digits with a figure: non-figure spans remove whole figure tokens as a multiset (`withoutTokens`), not a substring, so figure "0" no longer eats a digit of "2026-05".
  - Reconcile no longer blocks falsely on a processed row whose cells are all null, or on blank upload rows (interior or trailing). The writer emits a valueless stub cell so every such row keeps its `<row>` element, and processed rows are counted from cell elements in the table span. A row that is really dropped still blocks. This closes the Task 12 deferral.
  - `src/engine/data/typing.ts` held a raw U+0000 byte (git treated it as binary). The sheet key is now `JSON.stringify([file, sheet])`.
  - One `HEX_COLOR` (`#RGB` or `#RRGGBB`) is now used by `themeIssues`, `safeColor`, the design-lint `luminance` and the pptx `hex()`. `#B58B2` fails closed, and `hex()` expands `#RGB` and throws on anything else.
  - A calc step whose `columnId` names a declared source column was overwriting real data. It is now `schema.invalid` (in `validateSpec`, with a guard in `applySteps`). A declared virtual column (`source.header === ""`) or an undeclared one is still accepted.
  - The shared constants now live in one module, `src/engine/text.ts`: the long dash, the placeholder grammar, the 20px minimum font, the Arabic-Indic digit ranges, `HEX_COLOR` and figure tokens. Relationship-target resolution was left in its two call sites, because their inputs differ (rels path vs part map) and merging them was not cheap.
  - A second end-to-end fixture (`__fixtures__/twoDatasets.ts`) has two datasets, a page filter and a visual filter on `{{param:month}}`, a 40-row table that continues onto «(يتبع)» slides, and a 40-category bar with «أخرى». It issues with every gate passing, and its figures are asserted.
- `package.json` / `package-lock.json`: version 157.0.0; `pptxgenjs` and `jszip` as runtime dependencies of the engine.
- `src/data/changelog/latestUpdates.generated.ts`: regenerated from the edit logs.

Deferred, from the controller ledger: F5, the Reflex and Finish lint passes (only the F1 token-pair contrast check ships); slicers; charts in the workbook; buttons and logo; the browser (canvas) text measurer (tests use the fixed-advance one); fixing `LIMITS` by measurement (all provisional, Milestone 3); the review Minors deferred to Milestones 2 and 3. Real PowerPoint and Excel verification stays a manual release check until Milestone 3.

**Migration/rollback:** None needed. The engine is a new, isolated module under `src/engine/`. Nothing in the app imports it yet, it changes no workspace file format, and it writes no host files. Rollback: revert the engine commits on `claude/pptx-poc` back to `8c6950e8`, including the `package.json` dependency move.
