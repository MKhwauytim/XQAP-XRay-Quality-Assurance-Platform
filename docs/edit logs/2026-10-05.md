## v151.0 — 2026-10-05 — Add (reports): comprehensive executive report (completed samples; system + optional workbook)

**Why:** Management wanted one executive report covering every completed sample across all system months plus historical months that only exist in an external Excel workbook (Q1/Q2/Q3 sample sheets). The existing executive report is single-month, population-scoped and system-only. SheetJS (the vendored `xlsx`) cannot read the 144 MB workbook (it exhausts memory), so a dependency-free reader was chosen over upgrading or replacing the vendored library.

**What changed:** New Reports sub-tab «تقرير تنفيذي شامل» (`reports/comprehensive-executive`) that builds a completed-samples-only executive report as a document edition and an XLSX edition. Inputs: all system months loaded through the existing loaders, plus an optional uploaded workbook; on the same image id + month the system record wins (`mergeWithSystem`), and duplicates are counted and shown. `executiveReportData` gained a `rowsOverride` input so the builders can be fed pre-merged rows, and `ReportModel.scope = "completed-only"` suppresses population, coverage and target figures in the document and XLSX editions; the full scope output is byte-identical (snapshots unchanged). The workbook is read by a dependency-free zip/XML reader (`zipReader`, `sheetXml`, `readWorkbook`, `workbookColumnMap`) running in its own worker. Real-file smoke on the 144 MB workbook in Node: Q1_Sample 18,330 / Q2 20,166 / Q3 25,209 rows, 45,657 completed, 4.7 s, about 613 MB peak RSS. Catalog ruling: the sub-tab uses the ALL_ROLES catalog entry with default-off permission-matrix rows for guest/employee/supervisor and edit for manager/admin. Also on this branch (see v150.46 entry above): the seedless answer chain repair and isolated oversight-queue reads.

**Deferred follow-ups:** deck v2/v3 are not offered for the comprehensive report in v1; the document's part numerals/rail still list all five parts; Q*_Pop, بطاقة العمل and data-issue sheets are not read; the single `done` postMessage of about 45k rows has not been verified in a real browser worker; the real in-browser upload of the 144 MB workbook (File System Access workspace + native pickers) is not verified.

**Migration/rollback:** No on-disk format change; workbook data is memory-only and nothing is written to the workspace. Rollback = revert the branch.

## v150.46 — 2026-10-05 — Fix (answers): fold a seedless answer chain with an empty legacy baseline; isolate one assignee's unreadable answers in the oversight queue

**Why:** An employee's January answer chain had events but no `migration-seed` marker, so `foldAnswerEvents` threw `XQ-ANS-005` for that employee. The oversight queue reads every assignee with one `Promise.all`, so the admin's whole Referrals queue (and that employee's own) showed «تعذر تحميل البيانات» while other employees, served from their mirror, still worked.

**What changed:** `foldEmployeeEvents` now folds a seedless chain from an empty baseline when the employee's frozen legacy snapshot is empty (the missing marker could only have seeded nothing), logging `answers:fold:seedless-chain-repaired` once per month/user. A non-empty legacy snapshot is still refused (baseline genuinely ambiguous, §8/§10). Separately, the oversight queue now isolates each assignee's answer read: one unreadable employee is logged and named in a new warning (`ew_answers_partial_load`) instead of blanking the view.
