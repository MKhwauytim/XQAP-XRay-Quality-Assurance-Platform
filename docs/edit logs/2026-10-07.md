## v152.0 — 2026-10-07 — Add (deck2): editable static text in the executive deck, saved as named presets

**Why:** The owner wanted to rewrite the wording of the executive deck (deck2) from inside the report and keep those rewrites as a named preset, leaving the default deck untouched. Everything the app computes or manages (numbers, percentages, dates, port/month names inside data text, table cells, chart values) must stay uneditable. Rejected: runtime auto-detection of "static" text (could silently expose app-managed strings) and per-slide keys (break when page counts change month to month).

**What changed:** Static text sites are stamped `data-edit="<default text>"` through `editAttr()` (`deck2/textEdit.ts`): slide eyebrow/headline/subhead (`v2Slide`), side-rail title and tabs, table-card titles, cover title, TOC titles/goals, section-separator title/blurb. Any text containing a digit (Latin/Arabic-Indic/Persian) is locked automatically, so data-bearing headlines are never editable. The default text is the override key, so a preset survives page-count/month changes and one edit applies to every identical string. A new "تحرير النص" toolbar button turns on `contenteditable="plaintext-only"` for the marked elements only; Save-as-preset / Restore-original appear while editing, edits that introduce a digit revert on blur, and the toolbar is hidden in print. Overrides ship in the page as escaped JSON (`<` -> `\u003c`) and are applied by the in-page script; `buildExecutiveDeckV2`/`openExecutiveDeckV2` accept `textOverrides`/`textPreset` (trailing optional args). Presets are stored in the workspace as `6-templates/deck2.text-presets.json` (`textPresets.ts`, CAS + `withResourceLock`, same pattern as `styleChoices.ts`). The opened report tab has no `opener`, so Save posts over a same-origin BroadcastChannel to `DeckTextPresetPicker` (Reports tab, shown for the v2 edition), which writes the file and replies; with no listening app tab the report downloads the preset as JSON instead. The picker also selects/deletes presets; the active id lives in localStorage `xray_deck2_text_preset_v1` (registered in `storageRegistry.ts`) and both launch sites (`TabView`, `ComprehensiveExecutive`) pass the resolved preset to `openExecutiveDeckV2`. Plain text only — no formatting editing, per the owner. Default deck output changes only by the added `data-edit` attributes, the toolbar button, its CSS and an empty overrides block; golden snapshots and three inline byte-identity guards were updated for exactly that.

**Migration/rollback:** New additive file `6-templates/deck2.text-presets.json` (`{presets:[{id,name,overrides,updatedAt,updatedBy}],revision,_writeToken}`); no existing file shape changes, so no migration. Rollback: revert the commit; an orphaned preset file is ignored by older builds. Not yet added to `templateFileRecovery.ts` / backup coverage — follow-up.
