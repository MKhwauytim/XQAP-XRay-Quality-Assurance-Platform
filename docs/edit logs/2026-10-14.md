## v153.33 — 2026-10-14 — Fix (deck3): one land/sea rule per port, error rates on their own bases, labelled marking base, defined agreement weights, «عادي» image quality = «متوسط»

**Why:** An audit of the real-data executive report found four inconsistencies. (1) Land/sea was decided two ways. Port pages used the first row's «نوع المنفذ» per port, which depends on row order, while the quality-vs-agreement page decided per row. A blank type silently defaulted to land. (2) Page 12 showed missed/false suspicion as a share of ALL answers (19.9% / 8.9%), while every other page used the سليمة / اشتباه answers (27.9% / 31.2%). (3) «متابعة تحديد موقع الاشتباه وجودة الصور» used an undisclosed base, so its quality split looked like it contradicted the quality pages. (4) «وزن السليمة / وزن الاشتباه» was never defined. Separately, the owner decided that image quality «عادي» means «متوسط».

**What changed:**
- New `portKind.ts` (`resolvePortKinds`). This is the one rule: each port takes the majority of its non-blank «نوع المنفذ» values, and a tie goes to sea. A port whose types are all blank is `unknown`. It is shown on its own «غير محددة النوع» pages and rows, never as land. The rule is used by `collectPortStats` (deck2/slideKit), `collectLevelAccuracyRows`, deck3 `collectPortAccuracy` and `collectQualityImageOutcomes`. The deck3 groups, statements and support sheets carry the unknown group when it is non-empty.
- New `errorShares` in deck3/slides.ts. Missed is taken over سليمة answers and false over اشتباه answers. It is used on page 12 (level table) and on the quality-vs-agreement page. The support sheet drops its "% of all answers" columns.
- Marking/quality page: the panel row is renamed «صور الاشتباه المفحوصة», and a page note names the base (suspicion images answered on both questions, not all examined images).
- `AGREEMENT_WEIGHT_NOTE` is a second line under the formula wherever it appears. It reads: وزن السليمة = إجابات السليمة ÷ إجمالي الإجابات، ووزن الاشتباه = إجابات الاشتباه ÷ إجمالي الإجابات. `FORMULA_NOTE_PX` is now 72 to fit it.
- `workbookColumnMap.ts`: `qualityLevel` maps «عادي» to «متوسط» for «مستوى جودة الصورة» only. `تقييم الاشتباه` is untouched.

## v153.31 — 2026-10-14 — Change (statements): compare each port with one fixed baseline per port type (إجمالي), not the rest of its type

**Why:** In الملاحظات والتوصيات the comparison figure changed from one observation to the next, for example «صور عالية الجودة · باقي المنافذ البرية». Each port was compared with "the rest of its type", so the judged port was taken out of the base, and the base moved with every port named. The owner wants one baseline per measure that never changes.

**What changed:**
- `findOutliers`: the baseline is the pooled share of EVERY port of the same type (land or sea), the same «إجمالي» row the report's port tables show. Every observation on the same measure and type now quotes the same comparison number. Ports below `minDen` still count in the baseline but are not themselves named. The old fallback to "every other port" is removed. `PortOutlier.othersShare` is renamed `baseShare`.
- Observation and recommendation wording: «باقي المنافذ …» becomes «إجمالي المنافذ …».
- The level observation's «إجابات كل مستوى» figure showed level 1's count only. It now shows both levels: «56,423 / 56,445».
- `statements.test.ts` rewritten for the fixed-baseline rule, including a case asserting that all flagged ports of a type share one `baseShare`.
