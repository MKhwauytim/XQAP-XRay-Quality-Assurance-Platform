## v131.10 — 2026-09-03 — Fix (executive-deck): fit the on-screen deck to the window and soften its flat card/table surfaces

**Why:** Two follow-up reports on the same page after v131.9's fullscreen
fix. (1) "The report section is way too zoomed in" — the ORDINARY scrolling
view, not fullscreen. A deck2 slide is a fixed 1120×630 design box rendered
1:1 with no fit-to-viewport behaviour outside fullscreen, so on a real
laptop it never fits the window: measured headless at 1366×657 (a 1366×768
screen's actual inner viewport) the slide bottom landed 125 px of sticky
toolbar + viewer padding past the fold, so only a fragment of any page was
ever visible. Zooming in made it worse rather than better: past
`@media (max-width:1152px)` the shared deck CSS reflows `.slide` to
`height:auto` single-column, which measured 774 px tall — taller still, no
longer a slide, and re-typeset at different font sizes (headline 48 px →
32 px), i.e. a layout that matches neither the design canvas nor print.
deck3 has had fit-to-window since it shipped (`--v3-scale`), and this deck's
own fullscreen mode got it in v131.9; the scrolling view was the one place
left without it. (2) "The UI on that page feels blocky and outdated" —
deck2's own header has said since it shipped that it is a content-first
phase awaiting a visual pass. Checked first whether deck3 (already reachable
today behind the Reports tab's «التصميم الجديد» toggle) could simply become
the default instead: it cannot — it renders 21 slides to deck2's 27, missing
the whole «القسم 4 — التغطية والمساءلة التشغيلية» section and the data-source
section, so switching editions would silently drop content. Polished deck2
in place instead.

**What changed:** (1) `.slide.v2` in the non-fullscreen viewer is now pinned
to its true 1120×630 design box and scaled to fit the viewer's content box
AND the visible window height via `zoom:var(--v2-scale,1)`, capped at 1 (the
deck is only ever shrunk to fit, never blown up), screen-only so print still
renders 1:1. `zoom` rather than `transform:scale()` because zoom scales the
box's LAYOUT size: the slide keeps centring itself and the scroll extent
stays honest, where a transform leaves a 1120 px-wide layout box that
mis-centres in this RTL document (measured: 4 px of phantom horizontal
scroll and a slide sitting 56 px off-centre at a 1024 px viewport) plus a
630 px hole under every shrunken slide. The shared `max-width:1152px` reflow
overrides are neutralised for `.slide.v2` at every width, since v2 now
scales instead of reflowing and those rules would only mismatch print and
overflow the fixed box (which clips silently). v131.9's
`DECK_V2_FULLSCREEN_SCALE_SCRIPT` is generalised — not duplicated — into
`DECK_V2_SCALE_SCRIPT`, one measurement path and one resize listener owning
both `--v2-fs-scale` and `--v2-scale`. Fullscreen also picked up `flex:none`
on the active slide: as a flex item of the fullscreen flex-centre layout it
was still being shrunk to the container width below a 1120 px CSS viewport,
distorting the 16:9 box (measured 1.446 instead of 1.778 at 911×437). (2) A
depth-and-surface pass appended to `DECK_V2_CSS`: the slide, its cards/tiles
and its tables were all drawn with the same flat 1px `rgba(255,255,255,.13)`
outline over a flat fill, so nothing separated a container from its
contents. Border tone, corner radius, layered elevation and a top hairline
highlight now put the slide, its panels and its tables on three distinct
levels; tables get softer row rules, a quieter zebra, a gold header
underline and tabular numerals. Light-theme counterparts ship for every
changed value. The pass deliberately touches NO box metric — paddings, font
sizes, row heights and grid templates are all calibrated against the fixed
630 px slide budget and moving any of them clips content silently — and no
table background fills, which several pages re-tint per section. Report
numbers, metrics and content are untouched throughout.

```ts
// deck2/index.ts — one script owns both scales
const DECK_V2_SCALE_SCRIPT = `(function(){
  var root = document.documentElement;
  function set(name, value){ root.style.setProperty(name, String(value > 0 ? value : 1)); }
  function fit(){
    set('--v2-fs-scale', Math.min((window.innerWidth - 32) / 1120, (window.innerHeight - 32) / 630));
    var viewer = document.querySelector('.deck-viewer-v2');
    if (!viewer) { set('--v2-scale', Math.min(1, (window.innerWidth - 32) / 1120)); return; }
    var cs = getComputedStyle(viewer);
    var availWidth = viewer.clientWidth - (parseFloat(cs.paddingLeft) || 0) - (parseFloat(cs.paddingRight) || 0);
    var toolbar = viewer.querySelector('.deck-toolbar');
    var chrome = (parseFloat(cs.paddingTop) || 0) + (toolbar ? toolbar.getBoundingClientRect().height + 22 : 0) + 24;
    set('--v2-scale', Math.min(1, availWidth / 1120, (window.innerHeight - chrome) / 630));
  }
  fit();
  window.addEventListener('resize', fit);
  function fitAfterFullscreenChange(){ requestAnimationFrame(fit); }
  document.addEventListener('fullscreenchange', fitAfterFullscreenChange);
  document.addEventListener('webkitfullscreenchange', fitAfterFullscreenChange);
  if (document.readyState === 'loading') document.addEventListener('DOMContentLoaded', fit);
})();`;
```

## v131.9 — 2026-09-03 — Fix (executive-deck): stop fullscreen presentation slide from overflowing on zoom/resize

**Why:** The executive deck's single-slide fullscreen presentation mode
(`body.deck-fullscreen .slide.deck-slide-active`) set only `width` from a
`min(calc(100vw - 32px), calc((100dvh - 32px) * 297 / 167))` formula and left
`height` to whichever other CSS rule won the cascade for that property. Any
time the fullscreen window's effective CSS-px width dropped under 1152 —
which ordinary browser zoom (Ctrl +/-) does constantly, since zoom changes
`window.innerWidth` exactly like a resize — the higher-specificity
`.slide.v2{height:auto}` narrow-viewport rule took over `height`, so the
slide's real (uncompressed, budget-calibrated) content height came out well
over 630px while width kept shrinking toward the viewport. The result:
the slide overflowed top/bottom or right/left of the screen, or was clipped
under the fixed side nav, with no scroll to reach the clipped part (single-
slide fullscreen has `overflow:hidden`) — reproduced and confirmed headless
via Playwright by toggling `body.deck-fullscreen`/`.deck-slide-active` and
sweeping viewport sizes that stand in for zoom levels (100/120/150/80/90/
110%, cycling back to 100% to rule out any CSS-side accumulation). A second,
narrower case also overflowed above the 1152px breakpoint: a short-but-wide
window (e.g. 1300×600) where the fixed 630px height alone exceeded the
available vertical space, since width and height were being fit against two
independent constraints instead of one shared aspect ratio.

**What changed:** The fullscreen active-slide rule now pins the slide to its
real fixed 1120×630 design box (matching the row-budget math every other
slide layout in this deck is calibrated against) and uniformly scales that
whole box down (or up) via `transform:scale(var(--v2-fs-scale, 1))` so it
always fits both viewport axes without distortion or clipping — the same
proven pattern deck3's `--v3-scale` already uses, and for the same reason
CSS alone can't do it: `transform:scale()` needs a unitless `<number>`, and
dividing a length by a plain number stays a length in CSS (the declaration
is silently dropped). `--v2-fs-scale` is computed by a small new inline
script (`DECK_V2_FULLSCREEN_SCALE_SCRIPT`, deck2/index.ts) as
`min((innerWidth-32)/1120, (innerHeight-32)/630)`, re-run on `resize` and
`fullscreenchange`/`webkitfullscreenchange`. Deck2-only — deck3 already has
its own always-on scale script and is unaffected. Re-verified headless after
the fix across the same zoom sweep plus extra short/tall/huge viewports: no
overflow in any case, and results are identical across repeated 100% checks
(no drift). The non-fullscreen scroll layout (side nav show/hide, slide
reflow at ≤1152px) was re-checked and is unchanged. One existing test
(`deck2.test.ts`) asserted the old fullscreen-rule selector verbatim as a
substring and was updated to match the new selector; the golden byte-
identical snapshot and the deck2 CSS-content snapshot were regenerated to
reflect the intentional CSS/JS change (`npm run test:run -- -u` limited to
`deck2`, verified all 398 deck2 tests plus the full 4330-test suite pass).
