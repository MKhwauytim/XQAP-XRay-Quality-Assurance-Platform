## v126.17 — 2026-08-30 — Add (reporting): wire sourceRevisions footer/sheet into population report

**Why:** Task 11's review (population-report-merge plan) found a real gap: `PopulationReportInput.sourceRevisions`
is computed by `TabView.tsx` and accepted by `PopulationReportModel`, but none of `deck.ts`,
`document.ts`, or `xlsx.ts` ever read `model.sourceRevisions` — silently dropping the spec's
"footer provenance note, same as today" requirement (§4.1) that `sampleReport.ts`/
`distributionReport.ts` both honored via `sourceRevisionsFooterHtml`/`sourceRevisionsSheetAoa`.
Task 11 had left an executable canary in `sourceRevisions.test.ts` documenting the no-op precisely
so this gap couldn't be silently forgotten.

**What changed:**
- `executive/deck3/index.ts`: `buildDeckV3Html` gains a fourth, optional `footerNote: string = ""`
  parameter. When non-empty, `SOURCE_REVISIONS_CSS` is appended to the `<style>` tag and the note is
  appended right after the slides markup. The interpolation is written as
  `${slides}${footerNote ? `\n${footerNote}` : ""}` (not an unconditional `${slides}\n${footerNote}`)
  specifically so an empty/omitted `footerNote` reproduces the exact prior byte sequence — this
  function is shared with the real Executive Report deck (`buildExecutiveDeckV3`, which never passes
  a fourth argument), so its own tests and output needed to stay byte-identical, not just
  behaviorally unaffected.
- `populationReport/deck.ts`: `buildPopulationDeck` now passes
  `sourceRevisionsFooterHtml(model.sourceRevisions, esc)` as `buildDeckV3Html`'s new fourth argument.
- `populationReport/document.ts`: `buildPopulationDocument` computes the same footer once and
  concatenates it into `<main class="content">` after the pages, adding `SOURCE_REVISIONS_CSS` to
  the `<style>` tag only when the footer is non-empty. The pre-existing `esc(model.monthLabel)`
  escaping (Task 11's earlier security fix) in the `<title>`/`.doc-brand-sub` interpolations is
  untouched.
- `populationReport/xlsx.ts`: appends a `مراجعات المصادر` sheet (`sourceRevisionsSheetAoa`) right
  before the single `XLSX.writeFile` call, gated by `hasSourceRevisions(input.sourceRevisions)` —
  the real file has one `writeFile` call at the end (not the brief's assumed early-return branch), so
  only one insertion point was needed.
- `sourceRevisions.test.ts`: flipped the two Task 11 canary tests (document + deck) from asserting
  "output is byte-identical with/without `sourceRevisions`" (the tracked no-op) to asserting the new
  positive behavior — output now differs, the populated case contains the source file name, and the
  unpopulated case still renders no `source-revisions` markup at all.
- Added one test each to `deck3.test.ts` (`footerNote` backward-compat + append-when-provided),
  `deck.test.ts`, `document.test.ts` (footer appears with a populated `sourceRevisions` map), and
  `xlsx.test.ts` (sheet appears when populated, is absent when not).
- No golden-snapshot regeneration was needed: none of `deck.test.ts`/`document.test.ts`'s existing
  snapshot fixtures populate `sourceRevisions`, and the conditional-newline fix above means an empty
  footer produces byte-for-byte the same HTML as before.
