## v126.13 — 2026-08-30 — Add (reporting): population report xlsx export

**Why:** تقرير المجتمع (population report merge plan, Task 9) needed a spreadsheet edition
alongside the deck (Task 6/7) and document (Task 8) editions — stakeholders who want to
re-sort/filter/pivot the same population/sample/distribution figures need raw sheet data, not a
fixed slide or paginated print layout. Like the other two editions it had to carry export-scope
support (`"population" | "sample" | "both"`, spec §9/D11) from the start.

**What changed:** Added `xlsx.ts`, exporting `buildPopulationXlsx(input, scope = "both")`. Builds
one `XLSX.WorkBook` via `book_new()`/`book_append_sheet()`/`json_to_sheet()` and writes it with
`XLSX.writeFile(wb, "تقرير_المجتمع_${monthFolderName}.xlsx")` — no HTML rendering, so unlike
deck.ts/document.ts there is no escaping/XSS concern here (SheetJS cells are plain data). Reuses
`STAGE_LABELS` imported from `fold.ts` rather than declaring a local copy (the brief's original
draft predated that export landing during Task 7's fix round). `scope !== "sample"` appends the
two المجتمع sheets ("المجتمع - المرحلة", "المجتمع - المنفذ"); `scope !== "population"` appends
all five العينة/التوزيع sheets together ("العينة - المرحلة", "العينة - المنفذ", "التوزيع - الموظف
والمرحلة", "التوزيع - الموظف والمنفذ", "التوزيع - CertScan") — no cross-sheet numbering to adjust,
just conditional `book_append_sheet` calls. No workflow-status columns appear in any sheet (only
سليمة/اشتباه/total result counts and CertScan/non-CertScan counts).

## v126.12 — 2026-08-30 — Add (reporting): population report document

**Why:** تقرير المجتمع (population report merge plan, Task 8) needed a full-detail, paginated A4
document edition alongside the existing slide deck edition (Task 6/7) — the deck is built for
projection/skimming, but stakeholders who need to read every port and every employee row in full
(rather than a fixed-slide summary) need a print-flow document that never truncates detail. This
task also had to carry export-scope support (`"population" | "sample" | "both"`, spec §9/D11)
from the start, since Task 7b had already retrofitted the same switch onto the deck edition.

**What changed:** Added `document.ts`, building on the new documentV3 A4 chrome (`docPage`,
`docCover`, `docClosing`, `docSectionDivider`, `docPageHeader`, `docKpiStrip`, `docTwoColumn`,
`docPaginateTable` from `../executive/documentV3/shared`, styled via `DOCUMENT_V3_CSS`). It reuses
`RESULT_HEADERS`/`resultRow` re-exported from `deck.ts` rather than duplicating the table-row
escaping logic, and `STAGE_LABELS` from `fold.ts` rather than redefining the stage-key→Arabic-label
map a second time. `buildPopulationDocument(input, scope = "both")` composes Section 1 (population
receipt/processing/stage/port breakdown), Section 2 (sample stage/port breakdown), and Section 3
(per-employee distribution by stage, port, and CertScan) as flowing A4 pages, gated by `scope`:
`scope !== "sample"` includes Section 1's pages, `scope !== "population"` includes Sections 2+3
together (never independently) — cover and closing always render. Unlike the deck edition, each
section's page-number counter (`pad(n++)`) is already local to that section's own build function,
so scope-gating needed no cross-section renumbering, just conditionally calling a section's
builder. Per-employee detail tables use `docPaginateTable`'s chunking (25 rows/page) so a month
with many employees spreads across as many pages as needed instead of truncating — verified with a
50-employee fixture asserting both the first and the last employee are present in the output.
`openPopulationDocument` follows the existing `openReportWindow` / `writeOrCloseOnFailure`
open-early pattern used by every other report/deck opener in this app.

```ts
export async function buildPopulationDocument(
  input: PopulationReportInput,
  scope: PopulationReportScope = "both"
): Promise<string> {
  const model = computePopulationReportModel(input);
  const pages: string[] = [docCover({ org, title: "تقرير المجتمع", periodLabel: "الفترة", periodValue: model.monthLabel, metaRows: [] })];
  if (scope !== "sample") pages.push(...(await buildSection1Pages(model)));
  if (scope !== "population") {
    pages.push(...(await buildSection2Pages(model)));
    pages.push(...(await buildSection3Pages(model)));
  }
  pages.push(docClosing({ org, title: "نهاية التقرير", closingLine: `تقرير المجتمع — ${model.monthLabel}` }));
  return `<!DOCTYPE html>...`;
}
```

## v126.11 — 2026-08-30 — Add (reporting): export-scope switch (population/sample/both) — deck retrofit

**Why:** Spec addendum §9 (decision D11), added mid-flight after Task 7 shipped: تقرير المجتمع
needs a 3-way export-scope switch — population-only (Section 1), sample-only (Sections 2+3
together), or both (default). Task 7's deck hardcoded absolute slide numbers assuming all three
sections always render, so this task makes slide numbering scope-relative before Tasks 8/9/10
build on the same pattern.

**What changed:** Added `PopulationReportScope = "population" | "sample" | "both"` to
`types.ts`. `buildSection1Slides` takes a third `scope` param (default `"both"`); its contents-slide
rows now come from a new `contentsRows(scope)` helper that includes the "المجتمع" row unless
`scope === "sample"` and the "العينة"/"التوزيع" rows unless `scope === "population"`; when
`scope === "sample"` the function returns after cover+contents, skipping Section 1's own content.
`buildSection2Slides`/`buildSection3Slides` take a new `startNum` parameter replacing their
previously hardcoded absolute slide numbers (`meta(9)`..`meta(15)`). `buildPopulationDeckSlides`/
`buildPopulationDeck`/`openPopulationDeck` take a `scope = "both"` parameter and compute
`totalSlides`/`s1End`/`s2End` from which sections are included, calling Section 2/3 builders only
when `scope !== "population"`. For `scope === "both"` the computed numbers reproduce today's
hardcoded values exactly (s1End=8, s2 starts at 9, s3 starts at 12, total=16), verified
byte-for-byte identical by a new test (`buildPopulationDeckSlides(model)` ===
`buildPopulationDeckSlides(model, "both")`).
