## v131.4 — 2026-09-01 — Add (changelog): سجل التحديثات tab — latest 10 updates, generated at build time from edit logs

**Why:** Owner request: a new top-level tab, «سجل التحديثات», showing the app's own latest 10 updates. The open design question was where that content comes from, since the app has no backend and no LLM at runtime to turn an edit-log entry into a plain-language summary the way a human (or an offline assistant session) can. Two options were on the table: (a) a hand-maintained Arabic list, kept current by whoever writes each day's edit-log entry, or (b) a script that mechanically extracts each entry's own heading (category + title) from `docs/edit logs/` at build time — always in sync, but showing the entry's original English/technical wording rather than a translated summary. The owner chose (b). Rejected: re-embedding the *entire* edit-log history into the bundle, which is exactly what the old "سجل الإصدارات" tab did before it was removed in v72.0 (2026-08-13) for bloating the single-file build; this stays small by keeping only the newest 10 entries.

**What changed:** Added `scripts/generate-changelog-data.mjs`, which reads every `docs/edit logs/*.md` file, parses each top-level `## vX.Y — YYYY-MM-DD — Category (scope): Title` heading, maps the CLAUDE.md category to one of four display buckets (Fix/Security → إصلاح, Add/Feature → ميزة جديدة, Change/Remove → تحسين, Refactor → إعادة تصميم — Docs/Chore/Test/Merge/anything else is dropped as internal housekeeping), sorts by date then version descending, and writes the newest 10 as `src/data/changelog/latestUpdates.generated.ts`. Wired as a `pre*` hook on `dev`, `build`, `typecheck`, `test`, and `test:run` in `package.json` so the generated file can never silently go stale relative to the edit logs — it regenerates before every one of those commands, and the freshly generated copy is also committed so a plain `git clone` + open-in-browser (no npm install) still shows real, if slightly older, content. Added the new tab itself, `src/components/Sidebar/Tabs/Changelog/`: a read-only list of the 10 entries, each with a colored bucket badge (reusing the existing `.ui-badge` variants — no new colors), its date (formatted in Arabic), version tag, and title (kept LTR/English inline, since there is no translation path for it). Registered in `tabCatalog.ts` as `changelog` (group "system", `ALL_ROLES` ceiling, no explicit `createDefaultPermissions()` row — every non-admin role defaults to "none" via the existing fallback, same pattern as `population/adhoc-import`'s admin-only launch default: grantable, not granted). Added six `changelog_*` label keys to `labelsStore.ts` for the tab's own chrome (title/subtitle/bucket names/empty state); they fall through automatically into Settings' generated "أخرى" label group, so no change was needed there.

**Migration/rollback:** No on-disk workspace format changes — this tab reads nothing from the user's workspace folder, only from the repo's own `docs/edit logs/` at build time. Rollback is deleting the tab's catalog entry, its `src/` folder, `src/data/changelog/`, the generator script, and the five `pre*` package.json hooks.

## v131.1 — 2026-09-01 — Fix (performance): stop overlaying multiple days' gaps onto one team-mode working-hours row

**Why:** In تقييم الأداء's team-mode working-hours chart (no employee selected), every gap for an employee — across every day in the current date range — was flattened onto a single 7:30–17:30 track keyed only by time-of-day. Gaps from unrelated days landed at the same horizontal position and visually overlapped, and the exploded chip list below the track piled every single gap from the whole range into one unreadable wall of text (reported as "hard to read and broken"). Selecting a single employee already rendered correctly — one row per day — confirming the per-day rendering was right, just not applied in team mode.

**What changed:** Team mode now builds one working-hours row per (employee, day) instead of one row per employee, reusing the same per-day segment builder the employee-selected view already used. An employee with no notable (small/medium/large) gap on any day in scope still collapses to a single summary row labeled with just their name, unchanged from before. Row labels combine name and day (`"<name> · <weekday day>"`), so `.um-perf-hour-row-label`/`-spacer` and the chip-list's `padding-inline-start` were widened (100px/108px → 182px/190px) to fit the longer text without truncating.
