# Edit Log — 2026-09-01

## v131.1 — 2026-09-01 — Fix (employee-workspace): stop the results screen's periodic refresh from re-reading the whole month on every tick

**Why:** The results screen (صور الأشعة - النتائج, `XrayInspectionResults`) unconditionally re-runs its full `loadData` — whole-month `sample.master.json`, distribution derivation, distribution log, referral/replacement logs, and (for a supervisor) every employee's answer file — on every app-wide data-refresh broadcast, including the periodic ~45s sync tick, regardless of whether anything relevant to this screen changed. `XrayReferrals` and `useApprovalData.ts` already moved to the family-scoped `subscribeToDataChange`; this screen was still on the blanket `subscribeToDataRefresh`, so an idle tab paid the full read cost every tick. A prior investigation found population is already correctly never loaded for employees, and population/sample/distribution files are already gzip-compressed above 2,000 rows (`storagePolicy.ts`) — this fix targets the one remaining unaddressed cost: needless periodic reloads. A prior attempt at also deferring the referral/replacement-log reads to first tab visit was dropped after finding it would reintroduce the exact "no refetch on view-mode toggle" regression an existing test already guards against, for files that are small to begin with.

**What changed:** `XrayInspectionResults`'s periodic-refresh subscription now uses `subscribeToDataChange(RESULTS_REFRESH_FAMILIES, …)` with `RESULTS_REFRESH_FAMILIES = ["requests", "distribution", "answers"]` (the same list `useApprovalData.ts`'s `DECISION_REFRESH_FAMILIES` already uses for the same data) instead of the blanket `subscribeToDataRefresh`. A periodic tick that changed only an unrelated family (notifications, feedback, manifest) now costs nothing; a manual toolbar refresh still always reloads (`subscribeToDataChange`'s unconditional "manual" semantics), and the initial mount / view-mode-toggle behavior is unchanged. No workspace file format changed — nothing here requires the admin-migration flow.
