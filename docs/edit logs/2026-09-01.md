## v131.3 — 2026-09-01 — Change (auth): move debug tools from demo session to admin, translate to English

**Why:** The diagnostics toggle (connection/sync/responsiveness/error panel + JSON export) was gated on `session.mode === "demo"`, so it only ever appeared for the demo account and never for a real admin session — the opposite of who actually needs it to debug a live workspace. Owner request: move the gate to a real admin session, and switch its (previously Arabic) labels to English since it is a technical/numeric diagnostics surface, not ordinary end-user UI.

**What changed:** `AdminToolbar.tsx`'s debug toggle, export button, and `DemoDebugPanel` mount now key off `isRealAdmin` (`session.role === "admin" && session.mode !== "demo"`) instead of `isDemo` — the same real-admin-only condition already used for the feedback button — so a demo session (which also carries the `admin` role) no longer sees it, and a real admin does. The manual-refresh sync-sample recording that feeds the panel's "last manual refresh" stat moved to the same condition. All `toolbar_debug_*` and `demo_debug_*` label values (panel title, section headers, stats, buttons) were translated from Arabic to English, and the panel's own text direction switched from `rtl` to `ltr` to match. Internal module/file names (`demoDebugStore.ts`, `DemoDebugPanel.tsx`, `demoDebugReport.ts`) were left as-is — renaming them is a separate, unrequested refactor.

## v131.1 — 2026-09-01 — Fix (performance): stop overlaying multiple days' gaps onto one team-mode working-hours row

**Why:** In تقييم الأداء's team-mode working-hours chart (no employee selected), every gap for an employee — across every day in the current date range — was flattened onto a single 7:30–17:30 track keyed only by time-of-day. Gaps from unrelated days landed at the same horizontal position and visually overlapped, and the exploded chip list below the track piled every single gap from the whole range into one unreadable wall of text (reported as "hard to read and broken"). Selecting a single employee already rendered correctly — one row per day — confirming the per-day rendering was right, just not applied in team mode.

**What changed:** Team mode now builds one working-hours row per (employee, day) instead of one row per employee, reusing the same per-day segment builder the employee-selected view already used. An employee with no notable (small/medium/large) gap on any day in scope still collapses to a single summary row labeled with just their name, unchanged from before. Row labels combine name and day (`"<name> · <weekday day>"`), so `.um-perf-hour-row-label`/`-spacer` and the chip-list's `padding-inline-start` were widened (100px/108px → 182px/190px) to fit the longer text without truncating.
