## v60.0 — 2026-08-07 — Fix (p0): comma input, modal portal, KPI shared load+template, sampling total, save progress, session persistence

**Why:** the owner walked the app end-to-end on real data (500k+ rows) and reported 42 defects, recorded verbatim in `docs/product/APP_WALKTHROUGH_FEEDBACK_2026-08-07.md`. A six-agent code-grounded study (`REWORK_PHASE1_STUDY_2026-08-07.md`) verified each against source rather than trusting the report — **and refuted two of the three defects that had been ranked most critical.** This entry ships the P0 slice: items that are blocking, already producing wrong output, or fixable at near-zero risk.

Two hypotheses were **rejected after investigation** and deliberately not "fixed":
- *CertScan % applied additively, causing 7,000 → ~9,000.* Refuted: quota is `Math.min`-capped at three layers and `hamiltonApportionment` allocations sum exactly to the request. **The draw algorithm was not touched.**
- *Stage aliases overlapping L1/L2 result aliases in source.* Refuted: `stage: ["STAGE", "المستوى"]` is disjoint everywhere. A first pass at overlap validation flagged the shipped defaults as broken — that was a **false positive** (see below) and was corrected before shipping.

**What changed:**

**1. The comma could not be typed into alias fields (blocking).** The inputs were controlled off a *parsed array*: `parseMappingAliases` does `.split(",").filter(Boolean)`, so a trailing comma produced an empty token that was filtered out, and the next render rebuilt the string via `.join(", ")` — erasing the comma before it could persist. Multi-alias entry was structurally impossible. New `useDelimitedListInput()` keeps raw text in local state as the input's `value` and parses only on blur/Enter, tracking the last commit so an external reset re-syncs without clobbering in-progress typing. `DelimitedListInput` wraps it for use inside `.map()` loops. Applied to **all 10 affected inputs** — column-mapping Risk/BI aliases (system + custom), the four stage-mapping inputs, and both sheet-pattern inputs.

**2. Alias-overlap validation — namespace-scoped.** Detects one field's alias appearing in another's. **The first implementation compared across namespaces and therefore flagged the untouched shipped defaults.** `"المستوى الاول"` is legitimately both a *column-header* alias for `xrayLevelOneResult` and a *cell-value* alias for stage `first` — column names and cell values are matched against entirely different things and never compete. A warning that fires on a clean install trains users to ignore every warning, which is the same failure mode as item 3. `AliasFieldGroup` now carries an `AliasNamespace` (`"column" | "stage-value"`) and overlap is only reported within one namespace.

**3. `نوع الحركة` reported as an unmatched column.** `movementType` is derived 100% from the sheet name (`detectMovementType`) and never consults a column alias, so "no clear match" was structurally guaranteed. Sheet-derived fields now say so instead.

**4. Modal backdrops covered only ~half the viewport — in all 9 modals.** No modal used `createPortal`; `App.css`'s `view-enter` animates `transform` on each tab wrapper, which per spec makes it a containing block for descendant `position: fixed`, trapping every backdrop inside the tab's box. New `ModalPortal` portals to `document.body` with a reference-counted scroll lock (safe for nested modals). Wired into all 9 modals / 13 backdrop instances. `ew-modal-backdrop`'s `z-index` was raised 700 → 10020 because a value that was fine inside a local stacking context sat below `FeedbackWidget` (1200) once portaled.

**5. Report Designer KPI tiles: N loads → 1, and a silent correctness bug.** Each `KpiRenderer` ran its own full `loadMonthPopulationFinal` → `loadSampleMaster` → `loadOrDeriveDistributionCurrent` → `loadAllEmployeeFiles` → `buildExecutiveReportRows` over the whole month, with no sharing between sibling tiles. **It also hardcoded `template: null`**, so tiles silently could not resolve label-based fields (image quality, marking, suspicion level, suspected types, smuggling method) — the same field/month showed a different answer in a tile than in the executive report. New `ExecutiveRowsProvider` loads once per `(directoryHandle, monthFolder)`, resolves `template.selection.json` → `loadTemplate`, and uses the deduped read helper. Context and hook are split from the provider per the existing `GlobalMonthContext` convention, so Fast Refresh works.

**6. The report customization dialog took ~30 minutes to open.** `handleOpenCustomizer` awaited `loadExecInput()` (full population + sample + distribution) before setting the dialog open, and `DeckDesignCustomizer` additionally ran the entire `buildExecutiveDeckV2` on mount — opening the dialog *generated a full deck* before any option was picked. The dialog now opens synchronously; the deck build moved behind an explicit "معاينة حية" button.

**7. Sample total silently exceeded the request.** Not an algorithm bug. `DEFAULT_SAMPLING_RULES` shipped `minRequiredCount` **equal to `value`** for stages 2–4, so lowering a stage's value was silently overridden by `Math.max(target, minRequiredCount)`; and `PhaseThreeSampling` showed **no running total before the draw** — the sum first appeared after it ran. Added a live running total using the now-exported `configuredTarget` (the same function the draw uses, so UI and algorithm cannot drift), an explicit `role="alert"` warning naming any stage whose floor overrode the entered value, and changed the default to `0`. **Existing saved configs are untouched.** A regression test asserts the owner's requirement that CertScan is a split *within* the requested total, never additional to it.

**8. Progress hit 100%, then saved silently for 10–15 minutes.** `safeWriteJson` had no progress callback; the bar tracked `processPopulation`'s in-memory work, and the write — up to 5 full-file passes for files over 512KB — was invisible. Added an optional `onProgress` reporting five phases, threaded to the Population save UI. Optional and additive: ~30 other call sites unaffected. Observability only; write semantics unchanged.

**9. Session did not survive a browser restart.** `sessionStore()` moved from `sessionStorage` to `localStorage`, keeping the 7-day TTL and the demo-mode carve-out. **The owner explicitly accepted the unattended-machine risk**; `SECURITY_MODEL.md` records it as a deliberate SEC-02 relaxation rather than a silent divergence.

**10. Approvals page + export columns.** Sort-order indicator instead of silently flipping between tabs; two one-off hex literals replaced with design tokens; `float:left` close button replaced with a flex layout correct in RTL; both ad-hoc modals unified onto `ModalPortal`. Export config gained the 8 fields present on the row but unexportable: `declarationDate`, the CertScan and BI-enrichment fields, and `levelOneEmployee`/`levelTwoEmployee`.

**Migration/rollback:** no workspace data format changed; no file on disk is written differently. The only persisted-behaviour change is the auth session moving storage key location — an existing `sessionStorage` session is not migrated, so users sign in once more after upgrade, then persist. Rollback is a code revert; `DEFAULT_SAMPLING_RULES`' new `minRequiredCount: 0` affects only newly created configs, so reverting cannot corrupt a saved one.

## v59.200 — 2026-08-07 — Change (edit-log): tier the protocol by blast radius + generate entries; refresh stale CLAUDE.md facts

**Why:** a CLAUDE.md audit scored the file 81/100 (B) — architecture and gotcha coverage are strong, currency is not — and surfaced that the edit-log protocol itself had become the dominant per-task cost. Measured across all 687 historical entries: 52,587 lines, averaging 76.5 lines/entry, of which only 13.9% sits inside code fences. The `Before:`/`After:` snippets are *not* the expense; the expense is three things the protocol never intended:

1. **An emergent full-gate `**Verification:**` convention.** It isn't one of CLAUDE.md's seven required fields, but every recent entry runs all nine gates plus a build. v59.198 was a **three-line comment-only change** and still paid the 193-file suite, `tsc -b`, `lint`, `check:complexity`, `check:hex-literals`, `check:bundle-size`, `check:release` and a full `build`. That is minutes of wall-clock proving nothing about a comment.
2. **`Lines:` cost three commands** (`count-lines` before, `count-lines` after, `git diff --stat`) and was quietly wrong: `git diff --stat` never lists untracked files, which is why v59.199's `Lines:` line degenerated into a hedging paragraph enumerating five new test files by hand.
3. **The metric measured itself.** `count-lines` counted `docs/edit logs/` — 52,557 of the old 291,010-line total, **18%** — so every entry inflated the next entry's number and the trend line tracked documentation growth as much as code.

Plus a structural double-write: "record it **before** applying any code edit" forces writing the `After:` snippet before the code exists, then revising it once the edit settles.

**What changed:**

**1. Tier ladder replaces the flat protocol.** Tier 1 (comments, docs, typos, test-only) → 1–2 sentences, no snippets, `lint` + `typecheck` + the affected test file. Tier 2 (most fixes/features, the default) → `Why:` + `What changed:`, snippets, full suite. Tier 3 (refactors, architecture, data formats, releases) → full prose, snippets, all nine gates + build. Tier 3's sweep is now explicitly the **release** gate, not the per-edit gate, with `RELEASE_CHECKLIST.md` named as the authority when actually cutting one.

**2. Entries are generated, not hand-written.** New `scripts/editlog.mjs` (`npm run editlog`) fills in version, date, changed-file list and `**Lines:**`, then prints the tier's gate list. It counts untracked files explicitly rather than trusting `git diff --stat`. `--append` inserts into today's file (creating it if absent, refusing a second file per date); `--sync-package` keeps `package.json` in step so `check:release` passes. Major versions are emitted as `{N}.0` rather than a bare `vN`, because `check:release` compares the heading against `package.json`'s first two segments and a bare `v60` can never match — 23 historical headings have that bare form and would fail the gate if one were ever the newest.

**3. Entries are written after the edit, not before.**

**4. `count-lines` excludes `docs/edit logs/` by default** (`--with-edit-logs` reproduces the old basis). New default total: **238,423**; old basis: **291,010**. Historical entries were all recorded inclusively, so the series has a documented basis change here rather than a silent one.
