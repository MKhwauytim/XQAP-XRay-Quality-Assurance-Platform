# Edit Log — 2026-11-11

## v160.6 — 2026-11-11 — Fix (exceptional cases): show the operator's image id in reports, exports and screens

**Why:** The owner reported that «حالات استثنائية» do not show the correct «معرف الأشعة» in the reports, on the platform, or in extracted data. An exceptional case is stored under an internal key, `ADHOC-adh-{import uuid}-{id}`, so it can never collide with a real population row, and it keeps that key after being merged into a real month (v158.1). Only the employee queue, the inspection panel and the results table unwrapped it (`displayXrayImageId`). Every other surface printed the storage key.

**What changed:** Each surface that prints an id now passes it through the one existing helper, `originalXrayImageIdAnyImport`. Stored ids, joins, answer keys and event logs are untouched, so no workspace file changes shape and nothing needs migrating.

- Executive workbook (rows, BI enrichment, fact table, result comparison, raw data sheets) and the executive document's per-employee row lists.
- Management report and workbook: the replacement records are unwrapped once in `managementModel.ts` (id and replacement id); the reason lookup still uses the stored id.
- Power BI export: `population.csv` and `sample.csv`.
- Per-employee XLSX mirror (`employeeXlsx.ts`).
- Population Browse: cell, XLSX export, and the worker's search, filter and sort, so a search for the real id finds the row.
- Phase 4 distribution rows and their id search.
- Referral approval: request titles, detail rows, history lines, the id chips and «نسخ», and the short description used in confirmations.
- Inspection results audit table (id, original, replacement).

`HistoryView.test.tsx` used the import id `adh-1`, a shape `createImportId` never produces, and pinned the storage key as the displayed text. It now uses a real-shaped id and expects the operator's id.

Not covered: two different reviewers' replicas of one fanned-out case (`-R1-`) now print the same id, which is correct for the operator but means an exported id is not unique per row for those cases.
