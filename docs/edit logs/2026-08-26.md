# Edit Log — 2026-08-26

## v125.0 — 2026-08-26 — Fix (executive-report/deck3): rebuild to the handoff design and restore the deck2 viewer chrome

**Why:** The v124 deck3 (PR #105) shipped as a loose approximation of the owner's
high-fidelity handoff (`docs/design/design_handoff_xray_qa_deck/`), and the owner
flagged both drifts explicitly: (1) the export had none of deck2's viewer chrome —
no side section nav, no header toolbar, no طباعة / PDF button, no fullscreen — even
though the spec said viewer mechanics reuse deck2's pattern; (2) the slide design
didn't match the handoff (rounded cards everywhere though the handoff forbids
border radius, a 2×2-cards matrix instead of the 4×4 grid, no cover logo/org
block, no ghost-numeral dividers, several slides showing the same rows in both
"land" and "sea" panels). Two of the drifts were outright bugs: divider slides
rendered white-ish text with **no dark background** (nearly invisible), and the
responsive scale rule `transform:scale(calc((100vw - 32px) / 1920))` is invalid
CSS (length where scale() needs a number), so slides never scaled down at all.

**What changed:** Full rebuild of the deck3 module to the handoff's exact
layouts, plus deck2 chrome parity:

- `theme.ts` — rewritten to the handoff tokens verbatim: no border radius
  (except the 16px 50% dots), tinted land/sea panels with 5px top rules and
  colored dot titles, dark `#10304f` dividers with the 280px ghost numeral,
  2px-navy table/section rules, the contents grid (`120px 1fr 420px 130px`),
  KPI bands, the 4×4 matrix grid, engine-agreement band, impact callouts with
  the 5px inline-start bar, and the handoff chart geometry. Also carries the
  deck3-skinned viewer chrome CSS (side nav, sticky toolbar, single-slide
  fullscreen, print = one 1920×1080 page per slide) and the `--v3-scale`
  variable that replaces the invalid pure-CSS scale calc.
- `index.ts` — `buildDeckV3Html` now emits the same chrome markup as
  `buildDeckV2Html` (nav + progress, toolbar with fullscreen + طباعة / PDF,
  slide prev/next + counter) and reuses deck2's `DECK_NAV_SCRIPT` /
  `DECK_FULLSCREEN_SCRIPT` verbatim, plus a new `DECK_V3_SCALE_SCRIPT` that
  owns the 1920×1080 fit ratio (viewport estimate before first paint, precise
  measure after DOM ready, both-axes fit in fullscreen).
- `slideKit.ts` / `chartKit.ts` — templates and chart primitives rebuilt to the
  handoff structures (slide shells with `data-section` hooks for the nav
  script, zero-padded `NN / 21` footers only on content slides, grouped
  glossary grids, level columns with color chips, tinted plots with capped
  centered bars, reference lines with edge labels, fixed-width centered groups
  for the sea chart, honest null-value gaps instead of 0% bars).
- `slides.ts` — all 21 slides rebuilt per the handoff and wired to real data:
  cover/closing with the ZATCA logo + organization lines; per-level population
  table with share bars and a data-derived حصر كامل/عدد ثابت column; port
  panels with per-type coverage, `population (sample)` cells and totals rows;
  the three-tile accuracy band plus a per-risk-level accuracy table; per-port
  accuracy panels with the three accuracy columns and bracketed counts; land/
  sea per-port charts with pooled type averages; per-level clean/suspicion
  charts; the full confusion matrix with row/column totals; L1-vs-L2 pooled
  five-row panels and per-port grouped charts; security-team agreement from
  `crossTeamMatrix` plus the risk-engine band (targeted → agree/disagree →
  reviewer-upheld split, via `engineVerdictOf`); marking/quality impact split
  with pinned callouts. All data-derived strings are escaped.
- `model/reportModel.ts` — exposes `stageAccuracy` (the existing
  `aggregates.byStage` fold) so the per-risk-level accuracy slides read the
  shared fold instead of re-tallying.
- `deck2/index.ts` — the two chrome scripts gain `export` (no behavior change;
  deck2 output byte-identical).
- Level fixed-count shares (2,500/1,875/1,875 in the handoff) derive from the
  real `monthlyTarget` (40/30/30%), never the placeholder 6,250.

**Migration/rollback:** No data-format change. `ReportModel.stageAccuracy` is
additive. Rolling back is reverting the commit; the «التصميم الجديد» toggle and
`deckEditionPreference` storage are untouched.
