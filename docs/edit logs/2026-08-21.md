## v108.0 — 2026-08-21 — Change (adhoc-import): move under إدارة بيانات الأشعة; skip redundant sample-master rewrites

**Why:** Two unrelated things, both closing out the rework.

The move is owner request 5 of the rework brief (`docs/architecture/ADHOC_IMPORT_REWORK_PLAN_2026-08-21.md`): the ad-hoc page should live under **إدارة بيانات الأشعة** rather than standing alone as a top-level tab.

The write skip is a correction to v106.0. That entry made `ensureAdhocSampleMaster` **always** rewrite, which was necessary — a fan-out plan's replica ids exist on no row yet, so a conditional write would have left them unbacked — but it also means an unchanged import rewrites the whole synthesized `sample.master.json` on every save.

**Three claims in the plan turned out to be wrong, and were only found by building it.** They are recorded here because each would have shipped silently:

- The plan asserted that `tabCatalog.test.ts` asserts catalog↔registry agreement, so a leftover `tabConfig` export would "fail the suite loudly". **Nothing in the repo compares `SIDEBAR_TABS` against `TAB_CATALOG`.** Leaving the export would have shipped a duplicate top-level tab with a fully green suite, whose permission lookup resolves to `none` for every non-admin.
- The rendered sub-tab element must be memoized. An inlined element re-rendered the entire hidden wizard tree on every Population tick.
- `computeMonthLoadScope` was typed `"process" | "browse"` and blocked the widened union.

**What changed:** `adhoc-import` becomes `population/adhoc-import`: the catalog entry is re-parented, `Population`'s `subTabs` is extended, and the component's `tabConfig` export is **removed** so `tabRegistry`'s eager glob stops registering it top-level. Both features move into `TAB_FEATURE_MAP["population"]`, `SUB_TAB_FEATURE_MAP` is extended, and five `population/adhoc-import` default permission rows are added — `getRolePermission` does no parent inheritance, so a sub-tab with no row of its own resolves to `none`.

**One real behavioural loosening, called out rather than buried:** the two ad-hoc feature toggles are no longer permanently restricted in the permissions matrix. Cascading off Population instead of off an admin-only tab, a manager now sees two live unchecked toggles. Defaults stay off and the `ADMIN_ONLY` ceiling still refuses the page itself, but this is a genuine widening of what an admin *can* grant.

`ensureAdhocSampleMaster` now reads first and returns early when the file already covers every required id with an identical payload. **It is a superset test, not an equality test** — the file may hold ids that are no longer required, and dropping them would delete rows that live assign events still name. Payloads are compared too, because a re-mapped column keeps every id while changing what each row says. A missing or corrupt file falls through to the write: a read failure must never turn into a skipped write.

## v107.0 — 2026-08-21 — Add (adhoc-import): three-step wizard, four assignment modes, CertScan-style column mapping

**Why:** Everything built since v105.5 — the source layer, the field catalog, the mapping model, the month binding, the row projection — **was unreachable by clicking**. The tab still ran the v1 single-shot upload, matching columns silently against the Population mapping template. That is precisely the failure this rework exists to remove: a file whose header reads `Image ID` produced zero valid rows, with no in-page remedy and no explanation of what the app had looked for.

**What changed:** The tab becomes a three-step wizard over the v106.0 model.

**Step 1 — المصدر:** file upload or Excel paste, sheet selection, import kind, and the month binding (isolated / a chosen month / derived from a mapped column).

**Step 2 — مطابقة الأعمدة:** the mapping workbench — arm a field, click a column header, the column binds and tints. Advancing is blocked while a required field is unmapped, and an unmapped L1/L2 pair names itself **plus the "declare a constant once" instruction**. Without that sentence an admin importing a bare image list would sit at a disabled button with no way to know the escape hatch exists — the hatch v106.1 made mandatory is only useful if the screen says it is there.

**Step 3 — المراجعة والتعيين:** projection runs over every selected sheet with **one shared `seenIds`**, so a duplicate id in sheet 2 is caught against sheet 1 rather than each sheet being deduplicated in isolation. Then the four assignment modes — specific rows to one employee, N per employee, a Hamilton percentage split (equal by default), or every row to every employee. Each mode previews through `planAdhocAssignment`, **the same pure function the write path uses**, so the number shown is the number written. Fan-out confirms through a danger dialog naming the total, since it is the one mode that multiplies workload.

An unsaved draft and an opened import share one state shape, and the refresh handler never touches editor state — clobbering an unsaved draft on a refresh broadcast has already been a real bug in this repo.

**Release mechanics:** the bundle budget is raised 3.80 → 3.90 MB raw, gzip held, on the same documented criteria as the two previous raises; the overage was ~49 kB (1.3%). Noted in `check-bundle-size.mjs` at the time: the orphaned v1 modules are real headroom for a later slice. *(That note was later proven wrong — see v112.0, where deleting them reclaimed zero bytes.)*

## v106.1 — 2026-08-21 — Fix (adhoc-import): never invent an L1/L2 result

**Why:** `xrayLevelOneResult` / `xrayLevelTwoResult` are typed `"سليمة" | "اشتباه"` on `PreparedPopulationRow` with no representable "unknown". v106.0.0's catalog made them optional so a bare image list (`kind: "sample"`) could be imported at all, and the bridge then filled the gap at projection time with `"سليمة"`. That is a fabricated clinical result: it flows into `sample.master.json`, gets assigned, and renders in the employee's review table indistinguishably from a result an actual reviewer recorded. The module header even documented the fallback as intended behaviour, with the `{ kind: "constant" }` source described as the path an admin *could* take — but nothing required them to, so "optional" quietly meant "invented". Making the declaration available was not the same as making it mandatory, and only the mandatory version cannot silently produce data.

**What changed:** Both fields are `required: true` again in `ADHOC_FIELD_CATALOG`, and `projectToDistributionRow`'s fallback is replaced by `requiredResult()`, which throws.

Requiring them does NOT reintroduce the v1 problem this replaced. v1 required a real COLUMN; here a `{ kind: "constant" }` source satisfies the requirement, so a bare image list is still importable — the admin declares "every row in this file is سليمة" once, it is recorded on the import, and it is attributable to a person rather than invented per row. `stage`, which v1 also required and which a sample file has no reason to carry, stays optional; that asymmetry is now explained in the catalog header.

`catalogValue` became generic over its fallback so it can return `null` for the required-field probe while still returning `string` for `certScanStatus`. An unresolved value can now only reach projection through a caller that skipped `validation.valid`, so the throw is a programmer-error guard, not an operator-facing path — the operator sees the row rejected in the review table instead, with the reason naming the field.

Test fixtures updated across four files (+20 tests net). Most were fixtures that simply needed L1/L2 populated. Four asserted the old optionality and were rewritten, with names corrected where they had gone stale. The interesting category was coverage that had implicitly relied on the fabricated fallback: "a bare list projects fine" is now two explicit tests — one proving a declared constant makes the import work end to end, one proving that with nothing declared every row is invalid and `ensureAdhocSampleMaster` writes zero rows rather than throwing, so the admin gets a rejection count and not a crash. Added alongside: a guard that a value outside the catalog's options (`"غير معروف"`) throws instead of becoming `"سليمة"`.

**Two things this does not yet reach.** The escape hatch is model-layer only: the tab still runs the v1 parse path and never builds an `ImportMapping`, so an admin cannot declare a constant through the screen until the v2 mapping step is wired into `AdhocImport/index.tsx`. Behaviour there is unchanged — that path has always rejected a row lacking L1/L2, which is also why the fallback was unreachable from the UI and stayed latent. Separately, a v2 record persisted while the fields were optional could hold rows stamped `valid: true` with null results; those would now throw at assignment rather than project. Both UI call sites catch and surface the message, so it degrades to an error banner, but the banner would show an English programmer-error string. If such records exist in the field, the fix is a normalizer that re-invalidates them on load.

Also gitignored `.netlify/`, the CLI's local site-link state, which appeared while deploying a preview build. It records which remote site this working copy pushes to — machine-local, and committing it would point every clone at one person's site.

## v106.0 — 2026-08-21 — Refactor (adhoc-import): record v2, distribution bridge, mapping workbench UI

**Why:** Phase 2 of the ad-hoc import rework — the integration slice, where v105.5's additive pure layers stop sitting beside the feature and start carrying it. Three shapes in v1 blocked that.

`AdhocRecord` stored assignment as three scalars (`assigned` / `assignedTo` / `assignedAt`), which can only describe **one** reviewer holding the whole import; fan-out — every row reviewed by every employee — has no representation in that shape at all. The record also carried no snapshot of the mapping that produced it, which is the v105.5 defect restated: a saved import re-derived its column rules live from a screen it does not own. And the feature's reach into sampling, distribution and answers was spread across `adhocImportAssignment.ts`, so every safety property had to be re-argued at each call site.

**Editing `adhocImportTypes.ts` in place was rejected.** Five modules import it, so mutating the shape would have broken the build until every downstream slice landed, and the parallel work in flight needed a tree that compiles at every step. It becomes the **v1 compatibility view** instead — which is exactly what let the existing tab keep compiling while the new UI was built beside it.

In the workbench, **one identity colour per mapped field was rejected**: 19 identity colours are indistinguishable from one another and would collide with the semantic palette. Colour encodes mapping *state*; the binding itself is named in text on each field row.

**What changed:** Three pieces.

**Record v2 + migration.** `AdhocRecord` gains an `assignments` array replacing the v1 scalars, a snapshotted mapping, and a month binding. v1 records are upgraded **in memory on read** and never written back on their own; the legacy scalar fields keep being written for one release so an older build can still read the file.

**Distribution bridge.** `adhocDistributionBridge.ts` is now the only module in the feature that touches sampling, distribution or answers; `adhocImportAssignment.ts` becomes a thin legacy adapter over it. Every v1 safety property survives the move and is re-tested: stale-record re-read, closed-gate refusal, live-roster revalidation, `ownedIds` idempotency, a shared `eventAt`, and sample rows written before any event names them. Two deliberate behavioural changes: `ensureAdhocSampleMaster` now **always** rewrites, because a fan-out plan's replica ids exist on no row yet; and a plan is **rejected whole** if any target is unassignable, rather than silently dropping that reviewer's slice.

**Mapping workbench UI.** Arm a field, click a column header, the column binds and tints — `CertScanGrid`'s mechanic, reused so the interaction is already familiar. There is **no mutual eviction**: auto-clearing a field that had scrolled out of view would be silent data loss, so duplicates stand and are flagged instead. Headers are `button`s rather than clickable `th`s, for keyboard and screen-reader reachability.

**Known issue, shipped knowingly and tracked as the next change:** an unmapped L1/L2 pair falls back to `"سليمة"` at projection time, which **fabricates a clinical result**. It must not reach a release as-is — fixed in v106.1.

## v105.5 — 2026-08-21 — Refactor (adhoc-import): own type contract + shared workbook reader + source layer

**Why:** The ad-hoc import module reached into the Population tab's component subtree for four symbols (`normalizeRiskRow`, `NormalizedRiskRow`, `RiskSourceRow`, `worksheetToSourceRows`) and read its column aliases LIVE from `populationConfig.mappingTemplates[0]`. Two things follow from that, and both are defects rather than tidiness complaints. A `src/data/` module depending on `src/components/**` inverts the layering the rest of the data layer keeps. More concretely: because the aliases were read at parse time from a screen the ad-hoc page does not own, an admin editing the Population mapping template changed how an already-saved ad-hoc import parsed — the import's own record held no record of the rules that produced it. This is the first slice of the rework the owner asked for (`docs/architecture/ADHOC_IMPORT_REWORK_PLAN_2026-08-21.md`, correction C1), and it is deliberately additive: nothing here changes what the existing tab does today.

**What changed:** Three pieces, none of them wired into the running tab yet.

`adhocImportModel.ts` is the module's own type contract — source tables, a field catalog, the `column | constant | none` mapping source union, records carrying a snapshotted mapping, assignment planning, and a replica-aware `namespacedXrayImageId`. It is a NEW file rather than an edit to `adhocImportTypes.ts` on purpose: five modules import the latter, so mutating it would break the build until every downstream slice landed, and the parallel work in flight needs a tree that compiles at every step. The v1 types stay untouched until the record migration.

`adhocTextFolding.ts` holds the Arabic folding both the mapping and projection layers need (alef forms, ya/alef-maqsura, ta-marbuta, tatweel, diacritics, zero-width marks, plus Arabic-Indic digits). Duplicated from `columnMappingHints.ts` rather than imported, for the layering reason above; both copies are pinned by tests so a divergence fails a suite.

`worksheetRows.ts` moved from `Population/workbook/` to `src/data/workbook/`. This one is shared rather than duplicated, and the distinction matters: it is a general Excel reader, not pipeline logic, and it carries two fixes that would be silently re-broken by a reimplementation — large-integer IDs rewritten to strings before `sheet_to_json` (SheetJS stores a ≥16-digit ID as a float, which stringifies to exponential notation), and `blankrows: true` so `sourceRowNumber` is the operator's real spreadsheet line. Body is verbatim; the only behavioral delta anywhere is an `export` added to `makeUniqueHeaders` so the paste parser disambiguates duplicate headers identically to the workbook path — a pasted block and the file it came from must yield the same header names or a saved mapping stops matching. Three importers repointed, path only.

`adhocSourceTable.ts` reads both input forms into one `SourceTable` shape: `readWorkbookTables` (with a buffer-taking core so it is testable without a `File`) and `parsePastedTable` for the TSV Excel puts on the clipboard. Pasted `sourceRowNumber` counts the header as line 1 so the first data row is 2, matching the workbook path.

`adhocFieldCatalog.ts` + `adhocMappingModel.ts` are the CONSTRUCTION side of mapping: 19 fields (the 17 Population system fields with their alias lists copied in as literal seed data, plus the newly-mappable `certScanStatus` and a `studyMonth` / `شهر الفحص` entry), and the auto-detect that proposes a column for each. Only `xrayImageId` stays required — L1/L2 become declarable via a constant source, which is what lets a bare image list be imported at all. Contention is resolved by match STRENGTH in rounds (verbatim alias, then folded-equal, then containment) rather than catalog order: `portCode` carries the alias `"المنفذ"`, a substring of the header `"اسم المنفذ"`, so strict catalog order would hand the port-name column to `portCode` and leave `portName` empty on any file lacking a separate code column. A value with no confident canonical match is OMITTED from the seeded value mapping rather than guessed, so it surfaces as a decision the admin still has to make instead of a silently wrong one.

`adhocMonthBinding.ts` + `adhocRowProjection.ts` are the APPLICATION side. `parseStudyMonth` accepts a numeric date form only when every plausible reading agrees on the same (month, year) — `2026-05`, `05/2026` and `17/05/2026` resolve, `05/06` and `05/06/2026` return null. Refusing is the correct behavior: a guessed month files an entire study under the wrong period, silently, and the admin has no way to notice. Excel serials are detected before separator splitting because `.` is both a date separator and a decimal point, and the epoch is computed in UTC so an eastern timezone cannot push a first-of-month back a month. Projection resolves an enum to its CANONICAL spelling when a value matches only after folding — keeping `سليمه` would push the folding problem into the 25 files that read the strictly-typed `"سليمة" | "اشتباه"` union. An unresolvable enum value is reported with the offending text NAMED in the reason, which is the single biggest diagnostic improvement here: the old code said only "missing or invalid", leaving an operator to find the bad cell among tens of thousands.

`adhocTemplateMapping.ts` maps a spreadsheet column onto an inspection template's answer fields and coerces per `TemplateFieldType`, for the historical-study import. Partial coverage is the designed behavior, not a tolerated failure: an unmapped or null field is simply omitted from the sparse `FieldAnswer[]`, which is exactly right for a study that predates the template. `field.required` is deliberately ignored — required-ness is enforced by the live inspection form, not by a back-fill. A blank checkbox becomes null rather than `false`, because an unticked box and an unasked question are indistinguishable in historical data and writing `false` would assert the reviewer answered "no".

`adhocAssignmentPlan.ts` is the pure four-mode planner — explicit rows, count per employee, Hamilton percentage split (equal weights by default), and fan-out. It reuses `hamiltonApportionment` and the sampling RNG directly: the pool is shuffled from a seed derived from the import id, so a plan is deterministic on replay but not biased by spreadsheet order (a file sorted by port would otherwise hand one reviewer every row from one port). Fan-out is the only mode producing replicas, and `replicaIndex 0` reproduces the exact v1 id string, so nothing already on disk is invalidated. No I/O — the storage and event side is a later slice.

**Known follow-up (not a regression):** the workbook path drops a column that is blank in every data row, so it is not offerable for mapping; the paste path keeps such a column. Reconciled when the mapping UI lands — noted here so it is not rediscovered as a bug.

## v105.2 — 2026-08-21 — Fix (boot splash): the checklist no longer opens over a live app on a mid-session tab switch

**Why:** The "exactly once per boot session" guarantee rested entirely on `dismissed`, which is only ever set once the checklist has actually appeared and run its course. On the most common landing path it never appears at all — Population with no month selected registers zero boot sources — so `shown` never latches, `shownAtRef` is never stamped, the dismissal effect returns early at `if (shownAt === null)`, and `dismissed` stays false for the whole session. The session's *first* registration then arrives from whatever tab the user navigates to next (`XrayReferrals.tsx`'s initial-load branch, or `useMonthLoad.ts` on a month switch): `allLoaded` drops back to false and the "جارٍ تحميل بيانات النظام…" overlay opens on top of the app the user is already working in — precisely the frozen-mid-task sensation the feature exists to prevent. Only `timedOut` stood in the way, so the unprotected window was the first `timeoutMs` (8 s) after login, which is exactly when a real user makes their first tab switch. `BootSplashOverlay.lateRegistration.test.tsx` (v105.1) pinned the case down as a committed red test.

**What changed:** Added a per-session boot **window** to `BootSplashOverlay`: a new `bootWindowClosed` latch, armed with the rest of the session set and gating `visibleNow`, so the checklist may only make its *first* appearance while the window is open. Only the first appearance is gated — `showOverlay` still keys on `session.shown`, so a checklist already on screen when the window closes stays until it genuinely runs its course (`dismissed`) or the safety valve fires (`timedOut`). The window closes on whichever comes first:

- **the user's first interaction** — capture-phase `pointerdown`/`keydown` listeners. This is the precise signal: both known late-registration triggers (tab switch, month switch) are user-driven, and the capture-phase listener runs before React's delegated handler, so the window is already closed by the time the resulting render commits and the new tab's mount effect registers.
- **`bootWindowMs` elapsing** (new prop, default 2000 ms) — the backstop for a late registration no interaction preceded.

The window is armed only once `dataIsFresh`, since a session truly begins when its own `resetBootProgress()` lands (App.tsx's `useLayoutEffect`), not at mount; its setter re-checks `staleGeneration` as well as `key`, because a workspace switch A → B → A within one login regenerates the identical key string. A landing load slow enough to register after the window simply forgoes the courtesy checklist — the app underneath is mounted and running either way and its own per-tab loading state still shows — which is the safe side to fail on. The v105.1 red test is un-skipped, and two cases were added: the fast-clicker path (interaction inside the window) and a guard that a prompt landing registration with no interaction *still* shows the checklist, so the fix can't silently degrade into "never show it".

**Before:**
```ts
const visibleNow = dataIsFresh && !session.dismissed && !session.timedOut && !allLoaded;
```

**After:**
```ts
const visibleNow =
  dataIsFresh && !session.dismissed && !session.timedOut && !session.bootWindowClosed && !allLoaded;

useEffect(() => {
  if (!dataIsFresh || session.bootWindowClosed) return;
  const close = () => {
    setLatch((current) =>
      current.key === bootSessionKey &&
      current.staleGeneration === session.staleGeneration &&
      !current.bootWindowClosed
        ? { ...current, bootWindowClosed: true }
        : current // a newer session already re-armed this latch -- stale trigger, ignore
    );
  };
  const timer = window.setTimeout(close, bootWindowMs);
  window.addEventListener("pointerdown", close, true);
  window.addEventListener("keydown", close, true);
  return () => {
    window.clearTimeout(timer);
    window.removeEventListener("pointerdown", close, true);
    window.removeEventListener("keydown", close, true);
  };
}, [bootSessionKey, session.staleGeneration, session.bootWindowClosed, dataIsFresh, bootWindowMs]);
```
