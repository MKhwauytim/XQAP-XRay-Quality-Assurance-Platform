## v67.2 — 2026-08-11 — Fix (branding): skip PWA manifest injection on file:// origin

**Why:** Chrome DevTools on a double-clicked `dist/index.html` (`file://` origin) reported "Page is not served from a secure origin" plus three icon-load failures for the PWA manifest. PWA installation is impossible from `file://` (Chrome requires HTTPS/localhost), and each `file:` URL is its own unique opaque origin, so the manifest's `data:` icons can never load there either — the identical icons load fine on a served origin. Injecting the manifest on `file://` therefore produced only console noise and misleading DevTools warnings, never a working install prompt.

**What changed:** `registerAppManifest()` now returns before building/injecting the manifest when `isFileOrigin()` (the existing shared helper from `src/data/workspace/originDetection.ts`) reports a `file://` origin. Behavior on any served origin is unchanged. Also fixed a stale doc comment above the function that claimed the browser "ignores the manifest entirely" on `file://` — it no longer does since we skip injection ourselves. Updated `docs/product/HOSTING_FOR_INSTALL.md` to state plainly that installation can never be offered on `file://` and that the app deliberately doesn't inject the manifest link there.

```ts
export function registerAppManifest(): void {
  try {
    // Installation requires a secure origin (HTTPS or localhost); `file://`
    // is never one, so Chrome refuses to install regardless of what we
    // inject. Worse, each `file:` URL is its own unique opaque origin, so
    // the manifest's `data:` URI icons can never be fetched from it even for
    // display purposes. Injecting the manifest here would produce nothing
    // but console noise and misleading DevTools warnings ("Page is not
    // served from a secure origin", icon load failures) with no possible
    // benefit — so skip it outright rather than let the browser discover
    // that on its own.
    if (isFileOrigin()) {
      return;
    }
    const manifest = buildAppManifest(window.location);
```
