## v161.3 — 2026-11-26 — Fix (answers): recover answers an outdated app copy wrote, no green row for unsent answers, «إرسال إلى المجلد المشترك»

**Why:** Employees reported cases green and completed on their own PC while the admin, or the same employee signed in on another PC, found them unanswered, in an open month. Two causes in code. (1) A pre-v154 copy of the app knows nothing about the per-assignee layout: in a v2 month it keeps appending flat segments under `answers.events/` and reads them back itself, while every current client reads a v2 month only through the assignee folders, so those answers were invisible to everyone else (`strayFlatAnswers.test.ts` first case reproduces it: the answer is on the share and `loadEmployeeAnswers` returns nothing). (2) A submission still in this browser's outbox painted its row green (`isStudyCompleted` read the overlaid local answers), so an employee whose saves never reached the share saw finished work; the blocked causes were never logged where an admin could see them.

**What changed:**
- New `strayFlatAnswers.ts`: finds stray flat segments in v2 months and lands their self-saves through `replayPendingAnswers` (strict already-on-disk read, the event's own identity, newer save wins, never creates a month folder, honours closed months / read-only). Never moves or deletes the stray file; an unchanged file is not re-read in a session; supervisor / on-behalf events are skipped, not re-landed as self-answers. Each recovery is logged (`answers:stray-flat-adopted`) naming the employees, so the admin can find who runs an outdated copy.
- `PendingAnswerReplayRunner` runs that scan automatically at sign-in and every 5 minutes: every employee's strays for `answer-on-behalf` holders, otherwise the signed-in user's own.
- New `stuckAnswersReport.ts`: each blocked outbox cause (closed month, folder missing/unreachable, not responding, unreadable, read-only) is written once per session to the durable error log with the employee, count and months.
- Row colour: new `isCompletedOnShare` — a submission still queued on this device is not painted green (its badge already says «قيد الحفظ»).
- New always-visible «إرسال إلى المجلد المشترك» button (`sendAllAnswersToShare`): sends the unsent queue, re-checks every copy this browser holds as already sent against the share and re-sends what is missing, and recovers the user's stray answers — all through the same conflict-safe replay. A case a supervisor reopened is never overwritten (reopen keeps `lastSavedAt`, so the copy counts as already on disk).
