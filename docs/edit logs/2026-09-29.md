## v147.4 — 2026-09-29 — Fix (auth): every failed passcode attempt counts and overlapping submits are ignored

**Why:** `registerFailedAttempt` computed `failedAttempts + 1` from a render closure and `loginAsBootstrapAdmin` had no in-flight guard, so overlapping Argon2id verifies (key-repeat Enter, fast clicks) were counted as about one failure, weakening the lockout.

**What changed:** The failure counter is now a ref incremented in place. A shared `runGuardedLogin` ref guard lets only one verify run at a time (form login and hidden admin modal); extra submits are dropped. An `isVerifying` state disables the submit button, the username/password inputs, and the modal input and button. Lockout thresholds, timings and messages are unchanged.

**Before:**
```ts
const next = failedAttempts + 1;
setFailedAttempts(next);
if (next >= LOCKOUT_AFTER_ATTEMPTS) { ... }
```
**After:**
```ts
failedAttemptsRef.current += 1;
if (failedAttemptsRef.current >= LOCKOUT_AFTER_ATTEMPTS) { ... }
// login handlers: await runGuardedLogin(() => performEmployeeLogin());
```

**File:** src/auth/AuthGate.tsx - ref counter, in-flight guard, disabled controls.
**File:** src/auth/AuthGate.test.tsx - three jsdom tests (overlap ignored and controls disabled; lockout at threshold; correct passcode after failures logs in).

## v147.2 — 2026-09-29 — Change (answers): answer saves no longer run under casLoop; the decision is computed once, the append runs once, and every failure queues the answer

(final; supersedes the S2 entry above)

**Why:** `performAnswerWrite` wrapped an append to a private chain in a 14-attempt casLoop with no revision to compare; each attempt re-listed and re-folded the month (87 reads for one failing save on a 20-segment month). Replacing it must not weaken the safety net: month-folder resolution and the read side must still be retried, and any failure must leave the answer queued for replay.
**What changed:** the folder resolution, read, seed, fold and decide step runs once and is retried only if it throws (`retryDecisionRead`, shared jitter helper); then one deadline-bounded append. Failure mapping, telemetry and post-write refresh are unchanged (`casFailureFromCause`); on any failure the answer is queued pending, built from the caller's answer if the decision step never completed. A throw escaping the append's inner ladders fails to pending rather than being retried within the budget (accepted trade-off).
**Before:**
```ts
const mainDir = await getSampleMainDir(...); // outside any retry
return casLoop(async () => { /* read, seed, fold, decide, append */ }, { maxRetries: 14, ... });
```
**After:**
```ts
const decided = await retryDecisionRead(deadline, async () => { const mainDir = await getSampleMainDir(...); /* read, seed, fold, build */ return {...}; });
await appendAnswerEventSegment(mainDir, batch, writer, segmentConfig, { deadline, listedSegmentNames });
// catch: fallback pending candidate, then casFailureFromCause(...)
```

## v147.0 — 2026-09-29 — Fix (storage): sealed answer segments are no longer opened on every read, and one that grows is never missed

(final; supersedes the one above)

**Why:** `readSegmentTails` opened every listed segment on every read, so cost grew with the month's segment count. Skipping sealed segments is only safe if a sealed segment cannot grow, but a stable answer chain can be appended below its head (second tab with a stale memo, a thrown or lagging discovery listing).
**What changed:** (1) reader: skip `getFile()` for a name with a known offset that an earlier read confirmed sealed (higher-seq chain sibling listed), carrying its offset forward; chains are anchored on their seq-0 root. (2) writer: a stable writer never appends below the head of its chain as a successful listing (`listedSegmentNames`, from the answers read cache) showed it. (3) backstop: confirmations expire after 60 s and are dropped when the probe reports `answers` changed, on manual refresh, and after a backup restore that merged `answers.events` (which also clears the answers read cache).
**Before:**
```ts
reads[index] = await readListedEntry(dir, entry, ...); // every listed segment, every read
```
**After:**
```ts
if (skipped.has(entry.name)) return; // confirmed sealed + known offset + higher sibling listed + confirmation fresh
```
Migration / rollback: no on-disk format change (confirmations are in memory only); revert the commits to roll back.
